Architecture

CypherLite is an embedded, in-memory labeled property graph. The working set is RAM. Durable form is a fsync'd WAL plus a snapshot (Parquet by default, or GraphData JSON). Queries run against the live graph, not against the snapshot files.

The public type is cypherlite::Database. A Cypher string flows:

cypherlite-parser → cypherlite-front → cypherlite-planner → cypherlite-executor

GraphStore (cypherlite-engine, JSON .db files, Lance, --legacy) is withdrawn (ADR-0052).

┌──────────────────────────────────────────────┐
│              CLI / REPL / bindings           │
│   cypherlite-cli · Python · FFI · JS/Java/Go  │
├──────────────────────────────────────────────┤
│            Cypher parser / lowerer           │
│     cypherlite-parser  ·  cypherlite-front   │
├──────────────────────────────────────────────┤
│         Planner / executor / live graph      │
│   cypherlite-planner · cypherlite-executor   │
├──────────────────────────────────────────────┤
│         WAL + snapshot codecs                │
│              cypherlite-storage              │
└──────────────────────────────────────────────┘

Layer overview​

CLI / REPL (cypherlite-cli, cypherlite-splitter)​

  • Interactive mode — a cypher> prompt with readline-style editing on a TTY (ADR-0073), statement splitting, and .begin / .commit / .rollback / .quit.
  • Query mode — one Cypher string as a command-line argument.
  • Pipe mode — statements from stdin.

The CLI executes Cypher on cypherlite::Database. Results go through cypherlite-formatter. Bolt (cypherlite-bolt) is a transport in front of the same engine, not a second database.

Query engine (cypherlite)​

Database::query does not walk the parser AST as the execution plan. It:

  1. Parses Cypher (cypherlite-parser).
  2. Lowers the AST to planner IR (cypherlite-front).
  3. Binds and plans (cypherlite-planner) — MATCH rewrite, then a LogicalPlan.
  4. Executes that plan against a pinned MVCC snapshot of the in-memory graph (cypherlite-executor). Writes collect a private overlay, then commit as physical WAL redo.

See Query Execution.

Cypher parser (cypherlite-parser)​

A hand-written recursive descent parser: lexer, parser, AST. It covers the openCypher surface CypherLite supports (MATCH, CREATE, MERGE, SET, DELETE, WITH, UNWIND, RETURN, CASE, CALL subqueries and procedures, EXISTS, list comprehensions, reduce(), shortestPath, FOREACH, LOAD CSV, variable-length paths, schema DDL). Parse errors include a caret at the offending token.

cypherlite-ir is the planner AST, not a second product parser. cypherlite-front lowers the CypherLite AST into that IR.

Type system (cypherlite-model)​

CypherValue is the single representation for Cypher values: null, booleans, integers, floats, strings, lists, maps, nodes, relationships, paths, temporals, points, geometries, and vectors. Geometry conversions live here (geo crate).

The live engine stores compact interned records; public node/relationship maps are materialized when a query (or checkpoint) needs them.

Storage (cypherlite-storage)​

One write path: append physical redo to a fsync'd WAL (MDBWAL01), then apply_redo on the live graph. Open loads one snapshot codec per directory, then replays WAL. The matcher never scans Parquet or graph.json.

See Storage Engine.

No circular dependencies. cypherlite-model and cypherlite-core sit at the bottom of their stacks.

Bindings and targets​

  • cypherlite-python — PyO3 + maturin. sqlite3-style connect() / Connection / Cursor, plus execute_arrow() (Arrow IPC). Persistent paths are directories (WAL + snapshot codec).
  • cypherlite-ffi — stable cypherlite_* C ABI for other embedders (ADR-0054).
  • cypherlite-tck — openCypher TCK harness; the strict runner verifies 3896 of 3897 cucumber-expanded scenarios pass (0 fail; 1 documented skip).
  • cypherlite-cip-eval — Neo4j-CIP Gherkin beyond openCypher (ratchet baseline).

Design principles​

SQLite, not DuckDB​

CypherLite follows the SQLite product shape, applied to a live graph:

  • Zero configuration — a binary and (optionally) a directory.
  • Embeddable — Rust, Python, C/FFI (JS/Java/Go); Bolt is optional transport.
  • WAL + checkpoint — commits fsync the log; snapshots are for open/replay and recycle, not the query hot path.

It is not a columnar analytics engine. Parquet on disk does not mean DuckDB-style vectorized scans. Hops walk typed CSR in RAM.

Correctness first​

  • The parser is hand-written (no parser generators) for clarity, error recovery, and context-sensitive Cypher constructs.
  • Executor consumes LogicalPlan, not the parser AST; the engine is a custom row-based clause pipeline (not a relational planner like DataFusion) because graph traversal patterns don't map well to relational algebra.
  • 3896 of 3897 openCypher TCK scenarios pass under a strict harness that checks error class, error phase, and side effects — 0 fail, and the remaining one is a documented skip (an invalid-Unicode-hyphen lexing detail). The conformance gate is enforced in CI on every push and pull request, hard-failing on any non-skip-listed failure.

Key design decisions​

DecisionRationale
In-memory working setO(degree) hops on typed CSR; graphs must fit RAM
WAL then snapshotCrash recovery; codec (parquet/json) is pluggable (ADR-0050)
MVCC snapshot pinsReaders do not take a database RwLock
MATCH rewrite, no cost modelSelective seeds without DataFusion / LLVM
CypherValue enumOne home for coercion and TCK types
One product C ABIcypherlite_* (ADR-0054)

Vector search​

In-memory: HNSW when a vector index exists, otherwise a brute-force cosine scan. There is no Lance native path (ADR-0052).

Arrow and GeoArrow​

cypherlite-arrow converts CypherValue rows ↔ Arrow RecordBatch, encodes geometries as GeoArrow WKB, and ships Arrow IPC to Python.

See the Rust library reference.
