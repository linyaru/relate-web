Storage Engine

The matcher runs on an in-memory labeled property graph (interned records, typed CSR, MVCC). Disk is for crash recovery, not for scanning.

There is one write path (ADR-0014):

  1. Open — load one snapshot codec from the directory, then replay WAL records with lsn > checkpoint_lsn.
  2. Commit — append physical redo to the WAL and fsync, then apply_redo. The live graph is never the source of a commit.
  3. Checkpoint — pin an LSN, dump codec-owned store files, recycle closed WAL segments.

Parquet (or graph.json) is a snapshot of already-committed state. Queries do not read those files.

GraphStore (standalone JSON .db files, Lance, in-memory MemoryStore, --legacy) is withdrawn (ADR-0052).

Snapshot codecs​

One codec per directory (ADR-0050). Mixing graph.json with Parquet shards is an error. A mismatched --snapshot-format on an existing directory is an error.

CodecHow to choose (empty URI)On-disk store filesCheckpoint
parquet (default)omit flag, --snapshot-format parquet, or CYPHERLITE_SNAPSHOT_FORMAT=parquetmanifest.json, nodes/{lo}-{hi}.parquet, relationships/…Rewrite dirty id windows (ADR-0022)
json--snapshot-format json or CYPHERLITE_SNAPSHOT_FORMAT=jsonmanifest.json, graph.jsonFull rewrite of GraphData
:memory:URI :memory:In-process MemoryVfs + WALProcess-ephemeral; checkpoint() does not create OS files

WAL layout (wal/, magic MDBWAL01) does not change with the codec. manifest.json records "codec": "parquet" | "json" (absent codec means parquet). Existing files win over the flag.

./cypherlite ./mydata
./cypherlite --snapshot-format json ./mydata-json
use cypherlite::{Database, OpenOptions, SnapshotCodecKind};

let parquet = Database::open("./mydata")?;
let json = Database::open_with(
    "./mydata-json",
    OpenOptions {
        wal_dir: None,
        checkpoint_interval: None,
        memory_limit: None,
        snapshot_codec: Some(SnapshotCodecKind::Json),
    },
)?;

C and Python: set CYPHERLITE_SNAPSHOT_FORMAT=json before opening an empty directory to select GraphData JSON. Import an old CypherLite .db file by copying it to <dir>/graph.json and opening with --snapshot-format json.

Persistence model​

Redo is physical graph ops (create/delete node and rel, set/remove property, add/remove label), not Cypher text.

WAL, snapshot files, and cdc/slots.json go through a synchronous virtual filesystem (NativeVfs for a directory path/file://, BundleVfs when the path ends with .cl — ADR-0074 — MemoryVfs for :memory:). The virtual tree is unchanged; a .cl file is that tree packed into one host file.

On a filesystem directory URI:

<dir>/manifest.json
<dir>/nodes/{lo}-{hi}.parquet    # parquet codec
<dir>/relationships/{lo}-{hi}.parquet
<dir>/graph.json                 # json codec instead of shards
<dir>/wal/NNNNNNNN.log
use cypherlite::Database;
let db = Database::open("./graph.cl")?; // one host file (ADR-0074)
  • A commit is durable after WAL sync_all (group commit may share one fsync among waiting writers).
  • Crash recovery: load snapshot, replay the log. Uncheckpointed committed statements survive; an overlay that never reached WAL does not.
  • :memory: uses the same types in-process. Nothing is written to disk.

Engine object-store URIs (s3://) are withdrawn for this product (ADR-0044). Durability is a local directory or a .cl bundle file.

Checkpoint is rotate, dump, recycle — not stop-the-world truncate. The open WAL segment closes at 64 MiB, 10 000 commits, or a timer (default 300 s, CYPHERLITE_CHECKPOINT_INTERVAL_SECS; 0 disables the clock). Writers continue on the next segment. Persistent URIs also checkpoint on close.

CDC slots, if registered, hold WAL recycle until the consumer acks an LSN (ADR-0045). Cypher commits do not wait on publish.

Autocommit vs explicit transactions​

Default is auto-commit: one Cypher statement is one WAL commit. Isolation for readers is a snapshot at statement (or transaction) start.

Explicit transactions (.begin / .commit / .rollback, BEGIN / COMMIT / ROLLBACK on a connection):

  • Nested begin is an error.
  • Statements in the transaction share one overlay and one snapshot pin.
  • COMMIT appends the combined redo once. Empty commit is a no-op.
  • Connection drop or .quit with an open transaction rolls back.
  • After a statement error in a transaction, further statements fail until rollback (“poisoned” transaction).
  • CALL { … } IN TRANSACTIONS runs batches as their own durable units inside the enclosing statement; it is not a general savepoint mechanism.

openCypher TCK scenarios stay auto-commit.

Live graph​

  • Labels, relationship types, and property keys are interned.
  • Adjacency is typed CSR: type_id → Vec<RelId>. Deletes do not punch holes; visibility is rel_at / node_at at snapshot_ts.
  • Versions carry xmin / xmax. Incremental GC drops versions no pin still needs.
  • Snapshot pins are a lock-free slot table. The query path does not take a database RwLock. Readers and one apply_redo can run together; WAL append still serializes commit.

Memory cap​

Optional logical limit on the live graph and data-dependent indexes (ADR-0042), not process RSS. Growing writes that would exceed it fail with Error::Capacity at WAL append. DELETE and shrinking SET stay allowed. Open and replay always apply.

CYPHERLITE_MEMORY_LIMIT / --memory-limit / OpenOptions.memory_limit accept bytes or mb / mib / gb / gib.

There is no buffer pool or spill-to-disk. The working set must fit in RAM.
