quickstart

From zero to graph in 30 seconds.

No server to start, no credentials, no config. One binary, one file.

1

Install the agent skill

Teach your AI agents the CLI, the Cypher dialect, vector and spatial queries — one command, every detected agent. ↓

$ cypherlite skill install
$ cypherlite skill install --agent claude-code
2

Pick a database format ↓

No persistence — everything lives in RAM. Fastest option; ideal for tests, demos, and throwaway exploration.

$ cypherlite :memory: 'RETURN 1 AS ok'

A durable directory: fsync'd WAL plus Parquet snapshots (default). Open or create — same command. Checkpoint to graph.json instead with --snapshot-format json.

> Create a local graph database in ./mydata and open a shell→ loading skill cypherlite$ cypherlite ./mydata

A .cl bundle packs WAL, snapshots, and catalog into one host file — no sidecar files. Great for shipping a database with an app or agent.

> Create a single-file graph database mydata.cl→ loading skill cypherlite$ cypherlite ./mydata.cl
3

Create data

One-shot write with typed parameters — or LOAD CSV, pipe a .cypher file, or pull a subgraph from Neo4j/Aura. ↓

> Create Person nodes for Alice (30) and Bob (28)→ loading skill cypherlite$ cypherlite ./mydata 'UNWIND $people AS p CREATE (:Person {…})' --param 'people=[…]'
> Mirror the Person nodes from my Aura database into ./mydata→ loading skill cypherlite$ cypherlite pull --from neo4j.env --query 'MATCH (p:Person) RETURN p' ./mydata # durable path required
4

Query it

Same binary, same file — Cypher with a pretty table by default, JSON for pipes and agents. ↓

> List everyone in the database, youngest first, as JSON→ loading skill cypherlite$ cypherlite ./mydata 'MATCH (p:Person) RETURN p.name, p.age ORDER BY p.age'

Pick a format — memory, directory, or one file 
> Create a durable graph database in ./mydata, then run a count against it→ loading skill cypherlite
# in-memory — nothing written to disk (also `:memory:`)
$ cypherlite

# durable directory — WAL + Parquet snapshots (the default)
$ cypherlite ./mydata

# one host file — WAL, snapshot and catalog packed into a .cl bundle
$ cypherlite ./mydata.cl

# JSON snapshot codec instead of Parquet shards (empty directory only)
$ cypherlite --snapshot-format json ./mydata-json

# one-shot and piped scripts against any of them
$ cypherlite ./mydata "MATCH (n) RETURN count(n) AS n"
$ cypherlite ./mydata < setup.cypher

Created ./mydata (parquet codec, WAL in ./mydata/wal). One codec per directory — mixing parquet shards and graph.json is an error.
Create data — Cypher, typed params, CSV 
> Model a movie graph in ./movies: Person and Movie nodes, ACTED_IN relationships, unique Person names — then import extra people from CSV→ loading skill cypherlite
# schema first: constraint + index
$ cypherlite ./movies 'CREATE CONSTRAINT person_id FOR (p:Person) REQUIRE p.name IS UNIQUE'

# write Cypher — MERGE keeps it idempotent
$ cypherlite ./movies 'MERGE (m:Movie {title: "The Matrix"})
MERGE (p:Person {name: "Keanu"})
CREATE (p)-[:ACTED_IN {role: "Neo"}]->(m)'

# batch-create from a typed parameter (JSON scalars, repeatable)
$ cypherlite ./movies 'UNWIND $cast AS c
MATCH (m:Movie {title: c.movie})
MERGE (p:Person {name: c.name})
CREATE (p)-[:ACTED_IN]->(m)' --param 'cast=[{"movie":"The Matrix","name":"Carrie-Anne"}]'

# import a CSV file (values arrive as strings — coerce them)
$ cypherlite ./movies 'LOAD CSV WITH HEADERS FROM "data/people.csv" AS row
CREATE (:Person {name: row.name, age: toInteger(row.age)})'

Created 1 constraint, 1 Movie, 3 Person nodes, 2 ACTED_IN relationships; imported 3 CSV rows.
Query it — table for humans, JSON for pipes and agents 
> Who acted in The Matrix? Return name and role as JSON.→ loading skill cypherlite
# interactive shell — statements end with ;  (.help, .checkpoint, .quit)
$ cypherlite ./movies
cypher> MATCH (p:Person)-[r:ACTED_IN]->(m:Movie) RETURN p.name, r.role;

+--------------+---------+
| p.name       | r.role  |
+--------------+---------+
| "Keanu"      | "Neo"   |
| "Carrie-Anne"| null    |
+--------------+---------+

# one-shot, JSON for scripts and agents
$ cypherlite -json ./movies 'MATCH (p:Person)-[:ACTED_IN]->(:Movie {title: "The Matrix"}) RETURN p.name'

[{"p.name": "Keanu"}, {"p.name": "Carrie-Anne"}]

# other formats: -csv, -markdown, --mode jsonl · pipe-friendly, noheader optional
$ cypherlite -csv ./movies 'MATCH (p:Person) RETURN p.name, p.age' > people.csv

Keanu (role "Neo") and Carrie-Anne acted in The Matrix.
docker

One image, one command.

A multi-stage FROM scratch image: musl-native Alpine build, a runtime of three static binaries and the CA bundle. 65 MB, non-root, Bolt on 7687, auth on by default.

run
make docker builds it; the run publishes Bolt and seeds data on first boot 
# build the image and run it: Bolt on 7687, data in ./target/docker-data
$ make docker
$ make docker-run

# a one-off container with a preset credential and a seed query
$ docker run -p 7687:7687 -v "$PWD/data:/data" \
    -e CYPHERLITE_AUTH=cypherlite/secret \
    -e CYPHERLITE_QUERY="UNWIND range(1,100) AS i CREATE (:Person {id: i})" \
    cypherlite-bolt:0.9.2

# auth is on by default: the generated token is in the startup banner
$ docker logs <container> 2>&1 | grep "generated token"
auth: generated token for user cypherlite: 081024fbd538d05dbd177e0bb5e9808b
# persisted next to the database — the same token across restarts

Config resolution, most to least canonical: container args pass straight to the server (--bind, --auth, TLS flags); a mounted /config/seed.json drives seeding (ordered steps: query, load+query, pull+query); env one-liners (CYPHERLITE_QUERY, CYPHERLITE_LOAD, CYPHERLITE_AUTH). INSTANCES=N runs a test fleet — N servers, ports stepping from the base --bind port (-p 7687-7689:7687-7689 publishes the range). Ctrl-C and docker stop work. See the ADR and the README Docker section for the full contract.

reference

The concise reference.

CLI — flags, commands, exit codes

cypherlite [FLAGS] [DATABASE] [QUERY|-c QUERY] — the database path is optional (:memory: by default); a positional query runs once and exits.

$ cypherlite                                    # in-memory interactive shell
$ cypherlite ./mydata                           # durable directory, interactive
$ cypherlite ./mydata.cl "RETURN 1"             # single-file bundle, one-shot
$ cypherlite :memory: "RETURN 1 + 2 AS sum"     # one-shot, no files
$ cypherlite ./mydata < setup.cypher            # pipe a script

Flags — single- and double-dash both accepted; -- ends flag parsing:

-h, --help        usage
--version         version
--json / --csv / --markdown    output format shortcuts
--mode M          table | csv | json | jsonl | envelope | markdown | cypher
--noheader        drop column headers
--max-rows N     rows printed per statement; 0 unlimited (agent default 100)
--param N=V       bind a Cypher parameter (repeatable, JSON scalar)
--fetch-params N=SRC  fetch a URL or read a file, bind its JSON as $N (repeatable)
-c, --command Q   one-shot query
--snapshot-format F           parquet | json (empty directory only)
--wal-dir DIR               WAL directory (default <DATABASE>/wal)
--checkpoint-interval-secs N  timed checkpoint period, 0 disables
--memory-limit SIZE          live graph + index cap (bytes, mb/mib/gb/gib)
--durability-mode M         WAL durability (full|everysecond|snapshot; default full)
--load-csv-dir PATH         allow local LOAD CSV under this directory (default denied)
--read-only                 open an existing database without writing or checkpointing
--follow                   tail the WAL of a native database (implies --read-only)
--namespace NAME            session namespace (neo4j|system|system_ontologies)

Lifecycle commands — positional, first argument only:

$ cypherlite skill install [--agent NAME]   # agent skill bundle
$ cypherlite skill remove  [--agent NAME]
$ cypherlite upgrade [--yes] [--check]      # self-update (alias: update)
$ cypherlite telemetry off | status
$ cypherlite clone SOURCE DEST              # copy any db — dir ↔ .cl matrix; never writes SOURCE
$ cypherlite clone ./mydata ./backup.cl --to-snapshot-format parquet # .cl suffix picks the format; flag transcodes
$ cypherlite info ./mydata [--json]     # store metadata: layout, codec, checkpoint, counts — no open, no lock
$ cypherlite pull --from neo4j.env --query 'MATCH (p:Person) RETURN p' ./mydata
# pull: Neo4j/Aura subgraph → new local db (HTTP Query API v2, streamed, one checkpoint;
# --query takes inline Cypher, a ;-list, a file, or - for stdin; refuses a non-empty db)
$ cypherlite lab fs-to-graph ./src --db ./code-graph   # experimental
# lab fs-to-graph: import a directory tree as (:Folder)-[:CONTAINS]->(:Folder|:File),
# files keep content up to --max-content-bytes (default 65536); MERGEd on path, re-import is a no-op

Run cypherlite <COMMAND> --help for a command's own synopsis and flags (top-level --help stays short; both end with examples — CYPHERLITE_HELP_EXAMPLES=0 hides them). --version --json prints one JSON line. An unknown flag close to a real one gets a Did you mean '--read-only'? suggestion before the usage line. Exit codes: 0 success, 2 usage error, 6 rejected statement (syntax, semantic or type error — including a write on a --read-only database), 5 write conflict or store locked by another opener, 1 other runtime failure. In json, jsonl and envelope modes a failure also prints {"error":{code,exit_code,kind,message,retryable,…}} on stdout; a failed multi-statement run adds statement N of M failed; … on stderr. A path that collides with a command word stays reachable via ./ or after --.

Environment variables — each mirrors a flag:

CYPHERLITE_SNAPSHOT_FORMAT=json        # snapshot codec for an empty directory
CYPHERLITE_CHECKPOINT_INTERVAL_SECS=300 # timed checkpoint period, 0 disables
CYPHERLITE_MEMORY_LIMIT=4gb             # live graph + index cap
CYPHERLITE_TELEMETRY=0 · DO_NOT_TRACK=1   # opt out of CLI metrics
CYPHERLITE_MAX_ROWS=0 · CYPHERLITE_HELP_EXAMPLES=0  # lift the agent row cap / hide help examples
NEO4J_URI=… NEO4J_USERNAME=… NEO4J_PASSWORD=…  # pull source when --from is omitted
CYPHERLITE_LOAD_CSV_DIR=…             # allowed LOAD CSV directory

Telemetry is anonymous — command shapes, feature flags, an anonymous install id, a coarse environment tag. It never sends query text, file paths, or data, defaults to on, and only the standalone CLI collects it (not the embedded Rust, Python, or WASM APIs).

Shell dot-commands

Inside the interactive shell, dot-commands submit on Enter (Cypher statements end with ;):

cypher> .help          # command summary
cypher> .quit          # exit (alias: .exit; Ctrl-D works too)
cypher> .begin         # explicit transaction
cypher> .commit        # append combined redo once
cypher> .rollback      # discard the transaction
cypher> .checkpoint    # pin LSN, dump snapshot, recycle WAL
cypher> .info          # store metadata + live counts + catalog
cypher> .timer on      # per-statement timing

Default is auto-commit: one statement, one durable WAL commit. Explicit transactions share one snapshot; a dropped connection rolls back. Exiting with an open transaction rolls it back with a warning (batch modes exit 1). Ctrl-C cancels the current buffer.

Output formats

Seven formats, selected by flags — no in-session .mode command:

$ cypherlite ./mydata "MATCH (p:Person) RETURN p.name, p.age"      # table (default)
$ cypherlite -csv --noheader ./mydata "…" > people.csv
$ cypherlite -json ./mydata "…" > people.json
$ cypherlite --mode jsonl ./mydata "…" | jq .          # one object per line
$ cypherlite --mode envelope ./mydata "…"            # {columns, rows, truncated} per result set
$ cypherlite --mode markdown ./mydata "…"              # for docs & agents
$ cypherlite --mode cypher ./mydata "…"                 # Cypher literals

Flags work in one-shot mode, pipe mode, and the interactive shell. Under a detected agent harness a statement prints at most 100 rows (warns on stderr, exits 0; --max-rows 0 lifts it) and envelope reports "truncated": true.

Cypher — 100% openCypher TCK 2024.3 + GQL alignment

100% openCypher TCK 2024.3 — 3,893 / 3,893 scenarios pass, strict run (error class, error phase, side effects) enforced in CI. See the compliance report. On top of that, CypherLite ships full GQL alignment and the Cypher 25 feature set.

Read & write:

MATCH (p:Person)-[:FRIENDS_WITH*1..3]->(f) WHERE p.name STARTS WITH 'A' RETURN f
OPTIONAL MATCH, CREATE, MERGE, SET, REMOVE, DELETE, FOREACH, INSERT

Compose:

Schema DDL:

CREATE CONSTRAINT person_id FOR (p:Person) REQUIRE p.name IS UNIQUE

Namespaces — three fixed per store:

100+ built-in functions; CYPHER 5 / CYPHER 25 version prefixing; label expressions and GQL/GPM pattern matching.

Identifiers — unquoted Unicode (CYPHER 25):

RETURN 1 AS café    MATCH (n:Ärzte)-[:BESCHÄFTIGT]->(a) RETURN n.Größe  # non-ASCII, no backticks
WITH 1 AS a RETURN a AS union    {as: 1}    # keywords work as aliases, variables and map keys
Vector search

First-class vector() values, HNSW index top-k search (brute-force cosine fallback), similarity functions, and hybrid vector + graph queries in a single statement.

RETURN vector([0.1, 0.2, 0.3], 3, FLOAT32)               # typed vector
CREATE VECTOR INDEX idx FOR (a:Article) ON (a.embedding)
  OPTIONS {indexConfig: {`vector.dimensions`: 384, `vector.similarity_function`: 'cosine'}}
CALL db.index.vector.queryNodes('idx', 5, $q) YIELD node, score RETURN node, score
MATCH (a) SEARCH a IN (VECTOR INDEX idx FOR $q WHERE a.topic = 'graph' LIMIT 10)   # Cypher 25 SEARCH: top-k + pre-rank filter
CREATE FULLTEXT INDEX text_idx FOR (a:Article) ON (a.text)                        # keyword side of hybrid
vector.cosineSimilarity(a, b) · vector.euclideanDistance · vector.dotProduct · vector.manhattan
vector.normalize · vector.add · vector.subtract · vector.dimensions
Geospatial

WGS-84 and Cartesian points (2D and 3D), LineString/Polygon geometries, R-tree point index, and WKT/GeoJSON conversion.

point({latitude: 40.71, longitude: -74.01})       # geographic
point({x: 10, y: 20, z: 5})                      # cartesian 3D
point(l)                                          # a node or relationship works too — read as its property map
point.distance(a.location, b.location)            # meters (Haversine) / Euclidean
point.withinBBox(p, cornerA, cornerB) · point.withinDistance(p, center, meters)
CREATE POINT INDEX city_locations FOR (c:City) ON (c.location)   # R-tree
linestring([…]) · polygon([…]) · spatial.area · spatial.length · spatial.centroid
spatial.contains · within · intersects · overlaps · crosses · touches
spatial.fromWKT / toWKT · spatial.fromGeoJSON / toGeoJSON
Storage — WAL + one snapshot codec

The matcher runs on an in-memory graph; disk is for crash recovery. One write path: append redo to the fsync'd WAL, then apply. Snapshots capture already-committed state.

Shapes:

cypherlite :memory:                      # RAM only, nothing written
cypherlite ./mydata                      # dir: WAL + Parquet shards (default)
cypherlite --snapshot-format json ./d    # dir: WAL + graph.json (empty dir only)
cypherlite ./mydata.cl                   # one host file: WAL + snapshot + catalog
cypherlite --read-only ./mydata          # open existing store, no writes or checkpoints
cypherlite --follow ./mydata             # tail the WAL live (implies --read-only)
cypherlite clone ./mydata ./backup.cl      # dir → .cl file (reverse: clone ./backup.cl ./d); never writes source

Layout (directory codec):

<dir>/manifest.json
<dir>/nodes/{lo}-{hi}.parquet        # or graph.json for the json codec
<dir>/relationships/{lo}-{hi}.parquet
<dir>/wal/NNNNNNNN.log

One codec per directory — mixing Parquet shards and graph.json is an error. Checkpoints rotate at 64 MiB WAL, 10 000 commits, or a timer (default 300 s, --checkpoint-interval-secs). Crash recovery = load snapshot, replay WAL. --memory-limit caps the live graph (logical, not RSS) — the working set must fit in RAM. Optional CDC slots hold WAL recycle until acked. Stores carry a format version — opening an older store migrates it in place, hands-off.

Embedding & remote access

All language clients wrap the same C ABI (cypherlite-ffi) — no parallel protocols. Query results carry the same metadata everywhere: the resolved namespace and the query type (r/w/rw/s), from the Rust API through the C ABI to every client. Read-only open is available on every surface — Rust, Bolt, Python, C, JavaScript, Java, Go, and WASM — alongside the CLI's --read-only.

Rust — the public crate:

use cypherlite::Database;
let db = Database::open("./graph.cl")?;
let stats = db.execute("MATCH (n:Person) RETURN n.name")?;

Python — pip install neo4j-cypherlite, then import cypherlite (PyO3, in-process, plus Arrow IPC via execute_arrow).

JavaScript — Node: npm install @neo4j-labs/cypherlite (koffi over the C ABI; the platform package is an auto-selected optional dependency). Browser: npm install @neo4j-labs/cypherlite-wasm — in-memory, or durable OPFS via await CypherliteDb.open("opfs://name") in a dedicated worker.

Java / Go — FFI bindings over the same C ABI; prebuilt cypherlite-ffi tarballs ship for macOS, Linux, and Windows on the releases page.

Bolt — remote transport for the same engine: point any Bolt client at the cypherlite-bolt server. Basic auth is on by default — a token is generated at startup, printed in the banner, and persisted next to a persistent database (.auth-token); --auth user:password sets your own, --auth none disables. Bolt-over-WebSocket shares the same --bind (on by default, --no-websocket opts out, --ws-allow-origin widens the Origin policy), so neo4j-browser and the browser build of the official JavaScript driver connect out of the box.

$ cypherlite-bolt --help    # serve the database over Bolt
