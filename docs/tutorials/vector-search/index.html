Vector Search Tutorial

CypherLite supports vector properties on nodes, enabling semantic similarity search directly in Cypher queries. In this tutorial, you'll store document embeddings and query for similar content.

What are vectors?​

A vector (or embedding) is a list of floating-point numbers that represents the meaning of a piece of text, image, or other data. Vectors that are close together in space represent semantically similar content.

CypherLite stores vectors as list properties and provides three distance functions:

  • vector.cosineSimilarity() — angle-based similarity (most common for text)
  • vector.euclideanDistance() — straight-line distance
  • vector.dotProduct() — raw dot product

Setup​

./cypherlite ./vectors

Parquet snapshot by default. JSON codec: ./cypherlite --snapshot-format json ./vectors-json on an empty directory.

Step 1: Create documents with embeddings​

In a real application, you would generate embeddings using a model like OpenAI's text-embedding-3-small or a local model. For this tutorial, we'll use small 3-dimensional vectors:

CREATE (:Document {
  title: 'Introduction to Graphs',
  category: 'databases',
  embedding: [0.9, 0.1, 0.05]
});

CREATE (:Document {
  title: 'Graph Database Fundamentals',
  category: 'databases',
  embedding: [0.85, 0.15, 0.08]
});

CREATE (:Document {
  title: 'Machine Learning Basics',
  category: 'ml',
  embedding: [0.1, 0.9, 0.2]
});

CREATE (:Document {
  title: 'Deep Learning with Neural Networks',
  category: 'ml',
  embedding: [0.15, 0.85, 0.3]
});

CREATE (:Document {
  title: 'Cooking Italian Pasta',
  category: 'food',
  embedding: [0.05, 0.1, 0.95]
});

Step 2: Find similar documents​

Given a query vector, find the most similar documents using cosine similarity:

MATCH (d:Document)
RETURN d.title,
       d.category,
       vector.cosineSimilarity(d.embedding, [0.9, 0.1, 0.05]) AS similarity
ORDER BY similarity DESC
LIMIT 3;

The documents about graphs will rank highest since their embeddings are most similar to the query vector.

Step 3: Combine vector search with graph traversal​

Create relationships between documents:

MATCH (a:Document {title: 'Introduction to Graphs'}),
      (b:Document {title: 'Graph Database Fundamentals'})
CREATE (a)-[:REFERENCES]->(b);

MATCH (a:Document {title: 'Machine Learning Basics'}),
      (b:Document {title: 'Deep Learning with Neural Networks'})
CREATE (a)-[:REFERENCES]->(b);

Now find similar documents and their references:

MATCH (d:Document)
WITH d, vector.cosineSimilarity(d.embedding, [0.9, 0.1, 0.05]) AS sim
WHERE sim > 0.8
MATCH (d)-[:REFERENCES]->(ref)
RETURN d.title, sim, ref.title;

This is the power of a graph database with vector support: you can combine semantic similarity with structural graph traversals in a single query.

Step 4: Compare distance functions​

MATCH (d:Document)
RETURN d.title,
       vector.cosineSimilarity(d.embedding, [0.9, 0.1, 0.05]) AS cosine,
       vector.euclideanDistance(d.embedding, [0.9, 0.1, 0.05]) AS euclidean,
       vector.dotProduct(d.embedding, [0.9, 0.1, 0.05]) AS dotProduct
ORDER BY cosine DESC;

When to use which:

FunctionBest forRange
cosineSimilarityText embeddings, normalized vectors-1 to 1 (1 = identical)
euclideanDistanceSpatial data, absolute distances0 to infinity (0 = identical)
dotProductPerformance-sensitive queries on normalized vectorsvaries

Step 5: Create a vector index​

Create a vector index to accelerate nearest neighbor queries with HNSW:

CREATE VECTOR INDEX doc_embeddings
FOR (d:Document) ON (d.embedding)
OPTIONS {indexConfig: {dimensions: 3, similarity: 'cosine'}};

Now use the index for top-k search:

CALL db.index.vector.queryNodes('doc_embeddings', 3, [0.9, 0.1, 0.05])
YIELD node, score
RETURN node.title, score;

This uses the HNSW approximate nearest neighbor index for fast similarity search, returning the 3 most similar documents ordered by cosine similarity.

What you learned​

  • Storing vector embeddings as list properties
  • Using vector.cosineSimilarity() for semantic search
  • Combining vector search with graph traversals using WITH
  • Differences between cosine, euclidean, and dot product distances
  • Creating HNSW vector indexes for fast top-k search
