Geospatial Queries

CypherLite supports geospatial data through the point() type and point.distance() function.

Create geographic points​

Use latitude and longitude for geographic coordinates:

CREATE (:City {name: 'New York', location: point({latitude: 40.7128, longitude: -74.0060})});
CREATE (:City {name: 'Los Angeles', location: point({latitude: 34.0522, longitude: -118.2437})});
CREATE (:City {name: 'Chicago', location: point({latitude: 41.8781, longitude: -87.6298})});
CREATE (:City {name: 'London', location: point({latitude: 51.5074, longitude: -0.1278})});

Calculate distance between points​

point.distance() uses the Haversine formula for geographic coordinates, returning distance in meters:

MATCH (a:City {name: 'New York'}), (b:City {name: 'Los Angeles'})
RETURN point.distance(a.location, b.location) / 1000 AS distanceKm;

Find nearest locations​

MATCH (c:City)
WITH c, point.distance(c.location, point({latitude: 40.7128, longitude: -74.0060})) AS dist
RETURN c.name, dist / 1000 AS distanceKm
ORDER BY dist
LIMIT 3;

Radius search​

Find all cities within 1000 km of a point:

MATCH (c:City)
WITH c, point.distance(c.location, point({latitude: 40.7128, longitude: -74.0060})) AS dist
WHERE dist < 1000000
RETURN c.name, dist / 1000 AS distanceKm
ORDER BY dist;

(1000 km = 1,000,000 meters)

Cartesian points​

For 2D cartesian coordinates (e.g., floor plans, game maps), use x and y:

CREATE (:Sensor {id: 'S1', position: point({x: 10.0, y: 20.0})});
CREATE (:Sensor {id: 'S2', position: point({x: 15.0, y: 25.0})});

MATCH (a:Sensor {id: 'S1'}), (b:Sensor {id: 'S2'})
RETURN point.distance(a.position, b.position) AS distance;

Cartesian distance uses the standard Euclidean formula.

Combine with graph traversal​

Find the nearest connected city via a route:

MATCH (start:City {name: 'New York'})-[:ROUTE]-(connected:City)
WITH connected, point.distance(start.location, connected.location) AS dist
RETURN connected.name, dist / 1000 AS distanceKm
ORDER BY dist;

3D points​

Geographic points support a height property (meters above sea level):

CREATE (:Airport {
  name: 'Denver International',
  location: point({latitude: 39.8561, longitude: -104.6737, height: 1655})
});

Cartesian points support a z coordinate:

CREATE (:Sensor {id: 'S3', position: point({x: 10.0, y: 20.0, z: 5.0})});

3D distance calculations account for the additional dimension.

Bounding box and radius predicates​

Bounding box​

Check if a point falls within a rectangular region:

MATCH (c:City)
WHERE point.withinBBox(c.location,
  point({latitude: 30.0, longitude: -80.0}),
  point({latitude: 45.0, longitude: -70.0}))
RETURN c.name;

Radius check​

Check if a point is within a given distance of a center point:

MATCH (c:City)
WHERE point.withinDistance(c.location,
  point({latitude: 40.7128, longitude: -74.0060}), 500000)
RETURN c.name;

The third argument is the distance in meters (500 km in this example).

Geometry types​

Beyond points, CypherLite supports LineString and Polygon geometry types.

LineStrings​

Create a LineString from a list of points:

RETURN linestring([
  point({latitude: 40.7128, longitude: -74.0060}),
  point({latitude: 34.0522, longitude: -118.2437})
]) AS route;

Polygons​

Create a Polygon from a list of points (the first and last point must be the same to close the ring):

WITH polygon([
  point({latitude: 40.0, longitude: -75.0}),
  point({latitude: 41.0, longitude: -75.0}),
  point({latitude: 41.0, longitude: -73.0}),
  point({latitude: 40.0, longitude: -73.0}),
  point({latitude: 40.0, longitude: -75.0})
]) AS region
RETURN region;

Geometry measurements​

// Area of a polygon (in approximate square meters for WGS-84)
RETURN spatial.area(polygon([
  point({latitude: 40.0, longitude: -75.0}),
  point({latitude: 41.0, longitude: -75.0}),
  point({latitude: 41.0, longitude: -73.0}),
  point({latitude: 40.0, longitude: -73.0}),
  point({latitude: 40.0, longitude: -75.0})
])) AS area;

// Length of a linestring
RETURN spatial.length(linestring([
  point({x: 0, y: 0}),
  point({x: 3, y: 4})
])) AS len;

// Centroid of a polygon
RETURN spatial.centroid(polygon([
  point({x: 0, y: 0}),
  point({x: 10, y: 0}),
  point({x: 10, y: 10}),
  point({x: 0, y: 10}),
  point({x: 0, y: 0})
])) AS center;

Spatial predicates​

Test topological relationships between geometries:

// Does a polygon contain a point?
WITH polygon([
  point({x: 0, y: 0}),
  point({x: 10, y: 0}),
  point({x: 10, y: 10}),
  point({x: 0, y: 10}),
  point({x: 0, y: 0})
]) AS region, point({x: 5, y: 5}) AS pt
RETURN spatial.contains(region, pt) AS isInside;

Available predicates:

PredicateDescription
spatial.contains(a, b)True if geometry a fully contains b
spatial.within(a, b)True if geometry a is fully within b
spatial.intersects(a, b)True if geometries a and b share any space
spatial.overlaps(a, b)True if geometries a and b partially overlap
spatial.crosses(a, b)True if geometries cross each other's interior
spatial.touches(a, b)True if geometries share a boundary but not interior

These predicates work with all combinations of Point, LineString, and Polygon types, using ray casting for point-in-polygon, segment intersection for line crossings, and polygon overlap detection.

Crosses and touches examples​

// Do two linestrings cross?
WITH linestring([point({x: 0, y: 0}), point({x: 10, y: 10})]) AS line1,
     linestring([point({x: 0, y: 10}), point({x: 10, y: 0})]) AS line2
RETURN spatial.crosses(line1, line2) AS crosses;
// Returns true (X-shaped intersection)

// Does a point touch a polygon boundary?
WITH polygon([
  point({x: 0, y: 0}), point({x: 10, y: 0}),
  point({x: 10, y: 10}), point({x: 0, y: 10}), point({x: 0, y: 0})
]) AS region,
point({x: 5, y: 0}) AS pt
RETURN spatial.touches(region, pt) AS touches;
// Returns true (point is on the boundary)

Multi-geometry types​

CypherLite supports multi-geometry types through WKT and GeoJSON conversion functions:

// MultiPoint from WKT
RETURN spatial.fromWKT('MULTIPOINT((0 0), (1 1), (2 2))') AS mp;

// MultiLineString from WKT
RETURN spatial.fromWKT('MULTILINESTRING((0 0, 1 1, 2 2), (3 3, 4 4))') AS mls;

// MultiPolygon from WKT
RETURN spatial.fromWKT('MULTIPOLYGON(((0 0, 10 0, 10 10, 0 10, 0 0)), ((20 20, 30 20, 30 30, 20 30, 20 20)))') AS mpoly;

// GeometryCollection from WKT
RETURN spatial.fromWKT('GEOMETRYCOLLECTION(POINT(0 0), LINESTRING(0 0, 1 1))') AS gc;

Multi-geometry types round-trip through both WKT (spatial.toWKT()/spatial.fromWKT()) and GeoJSON (spatial.toGeoJSON()/spatial.fromGeoJSON()).

Spatial conversion functions​

Convert between geometries and standard formats. Supports Point, LineString, Polygon, MultiPoint, MultiLineString, MultiPolygon, and GeometryCollection types.

// Convert to GeoJSON
RETURN spatial.toGeoJSON(point({latitude: 40.7, longitude: -74.0}));
// Returns {type: "Point", coordinates: [-74.0, 40.7]}

// Convert from GeoJSON
RETURN spatial.fromGeoJSON({type: 'Point', coordinates: [-74.0, 40.7]});

// Convert to Well-Known Text
RETURN spatial.toWKT(point({x: 10, y: 20}));
// Returns "POINT(10 20)"

// Convert from Well-Known Text
RETURN spatial.fromWKT('POINT(10 20)');

// LineString WKT round-trip
RETURN spatial.toWKT(spatial.fromWKT('LINESTRING(0 0, 10 10, 20 25)'));

// Polygon GeoJSON
RETURN spatial.toGeoJSON(polygon([
  point({latitude: 0, longitude: 0}),
  point({latitude: 1, longitude: 0}),
  point({latitude: 1, longitude: 1}),
  point({latitude: 0, longitude: 1}),
  point({latitude: 0, longitude: 0})
]));

Spatial indexing​

Create a point index to accelerate bounding box and radius queries with an R-tree:

CREATE POINT INDEX city_locations FOR (c:City) ON (c.location);

When a point index exists, point.withinBBox() and point.withinDistance() queries use the R-tree to narrow candidates before applying exact geometric checks, significantly improving performance on large datasets.

The R-tree index is automatically rebuilt from stored index metadata when the database is reopened.
