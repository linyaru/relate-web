Limitations

CypherLite is 0.6.1. It is a lightweight, embeddable, single-process graph database — closer to SQLite than to a clustered graph server or a columnar warehouse. Several of these are scope choices, not bugs.

One graph per statement (no cross-graph queries)​

A CypherLite process operates on exactly one active graph at a time. The graph is chosen when the database is opened (cypherlite [DATABASE], Database::open, or the equivalent binding call) — the shell's .open / .attach / .use multi-database commands are withdrawn (ADR-0058). A single query always runs against a single graph:

  • Multi-database switching is withdrawn: you cannot open several databases in a session and switch between them, and there is no USE <graph> addressing of another graph inside a statement.
  • A leading USE <otherGraph> in front of a statement that reads or writes graph data — directly, or inside CALL { … } or CALL <procedure> — is rejected. USE g RETURN 1 (no graph access) stays a no-op.
  • No composite, federated, or sharded databases.

Transactions are single-level​

Single-level explicit transactions (.begin / .commit / .rollback and the binding APIs) over an autocommit default. Nested transactions are not supported. CALL { … } IN TRANSACTIONS batches its own durable units; it is not a savepoint mechanism.

Durability (when writes hit the WAL, snapshot codecs, poisoned transactions) is in Storage Engine and Autocommit vs. explicit transactions.

Durability: WAL plus one snapshot codec​

cypherlite::Database appends redo to a fsync'd WAL, then checkpoints to one codec per directory (parquet shards or a full graph.json rewrite). Open loads the snapshot and replays WAL. Codecs do not mix in one directory (ADR-0050). GraphStore --legacy JSON files are withdrawn (ADR-0052).

:memory: is process-ephemeral.

Single-process engine​

A directory-backed database is used from one process. CypherLite is not a multi-process or multi-writer client/server. Bolt (cypherlite-bolt) is still one engine. Concurrent threads in that process may read together; overlapping writers get write-write conflict at WAL append (no silent retry).

Whole graph held in memory​

The live graph is in RAM. Traversal is typed CSR; persistence is WAL + a snapshot. The working set must fit in memory. There is no paging, buffer pool, or spill-to-disk. An optional logical cap (ADR-0042) fails growing writes with Error::Capacity.

Size is “whatever fits,” not a fixed node count. This is not an out-of-core analytics engine.

Lance / GraphStore are withdrawn​

JSON GraphStore files, Lance directories, and --legacy CLI flags are not product surfaces (ADR-0052). Import an old .db by copying it to <dir>/graph.json and opening with --snapshot-format json.

The JSONL --server protocol is withdrawn with GraphStore. Language bindings call the engine in-process.

openCypher TCK: one documented skip​

CypherLite runs the openCypher TCK under a strict harness (it checks error class, error phase, and side effects, and fails on unknown steps). Of the 3897 cucumber-expanded scenarios, 3896 pass, 0 fail, and 1 is skipped — the skip is real, documented, and pinned by a test (EXPECTED_TCK_SKIPS) so it cannot drift silently:

ScenarioWhy it is skipped
Mathematical3 [1] — "Fail for invalid Unicode hyphen in subtraction"The query RETURN 42 — 41 (U+2014 em-dash) must raise SyntaxError: InvalidUnicodeCharacter at compile time. The engine raises a compile-time SyntaxError, but the lexer does not tag the InvalidUnicodeCharacter detail, so the strict class+detail+phase matcher rejects it. Retiring the skip means teaching the lexer to raise InvalidUnicodeCharacter.

This is the only TCK scenario CypherLite does not pass. The CIP evaluation suite (Neo4j Cypher beyond the TCK) is tracked separately at 5615/5629 (99.8%); its residual is documented in testdata/cip-eval/SWEEP-FOLLOWUP.md.

Not in scope for the embedded engine​

Role-based access control, user authentication, remote/composite/sharded databases, cluster topology, and server-settings administration. Those are multi-tenant server concerns, not a single-process library.
