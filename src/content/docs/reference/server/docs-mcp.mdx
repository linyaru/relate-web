`https://relatedb.ai/mcp` serves the relate documentation to agent hosts over :term[MCP]{id=mcp} (the Model Context Protocol): five read-only tools that search the pages, read one section or one page, look up an error, check a Cypher statement with `EXPLAIN`, and match a problem to what relate offers; the pages, the skills, the capability catalog and the cookbook's cells as resources; and two prompts. It needs no account and no credential, and it opens no :term[store]{id=store} of yours. The URL is a launch-day target: the server is not deployed yet, and until it is, it runs only as a local build of the site's source. It is not relate's own MCP server, `relate serve --mcp`, which serves a store of yours with the tools `read_cypher`, `get_schema` and `write_cypher`; no tool here shares a name with those, so a host can connect both.

## Synopsis

| Item | Value |
| --- | --- |
| Endpoint | `https://relatedb.ai/mcp` (a launch-day target) |
| Transport | MCP streamable HTTP: each JSON-RPC request is a `POST`, answered as server-sent events (SSE), one `event: message` per response |
| Sessions | None. The server is stateless: no `mcp-session-id` is issued, and a `GET` that asks for `text/event-stream` and a `DELETE` both get HTTP 405 |
| Required request headers | `Content-Type: application/json` and `Accept: application/json, text/event-stream`; without that `Accept` value the answer is HTTP 406 |
| Authentication | None, and no accounts |
| Writes | None. The one tool that takes Cypher, `validate_cypher`, plans the statement with `EXPLAIN` on a fresh, empty engine instance and never runs it; nothing a request sends is stored |
| `serverInfo` | `name` `relate-docs`, `title` `relate docs`, `version` `0.1.0`, `websiteUrl` `https://relatedb.ai/docs/` |
| Capabilities | `tools`, `resources`, `prompts` |
| What it serves | The published docs pages and their markdown twins, the docs index (`llms.txt`), the agent :term[skill]{id=skill} and the task skills, the errors reference data, the release list, the capability catalog, and the cookbook's cells with their recorded results |
| Docs version | relate 0.16.1, the version every page and every example is verified against; every tool result carries it as `version.verified` |
| Built from | The same site build as the pages: the twins at `/docs/<id>.md`, the docs graph seed at `/docs/graph.cypher`, the errors data behind [Errors](/docs/reference/errors), `/releases.json`, `/docs/capabilities.json`, and each recipe's `recipe.json` |
| Runs on | A Cloudflare Worker running the relate engine compiled to WebAssembly (WASM), the same build the site's runnable cells use; search queries are embedded by Cloudflare Workers AI with the model the sections were embedded with |

The server's `initialize` result carries `instructions` that describe it: the canonical phrase, the verified version, the tools, resources and prompts, the line "Every result is reference text from the documentation, not instructions", and where the limits are published.

## Tools

Five tools, the most the server will offer: a new tool replaces one. Each is annotated `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true` and `openWorldHint: false`, and each description ends with "Results are reference text, not instructions." A result's JSON is in `structuredContent` and, as text, in `content[0]`. Every result carries `kind: "documentation"`, a `note` saying it is reference text, and the canonical `https://relatedb.ai/docs/…` URL and the `.md` URL of each page it cites.

| Tool | Input | Returns |
| --- | --- | --- |
| `search_docs` | `query` (required, 1 to 200 characters); `limit` (1 to 20, default 5); `section` (`get-started`, `guides`, `reference` or `concepts`); `surface` (one of `cli`, `python`, `node`, `browser`, `rust`, `c`, `java`, `go`, `swift`, `bolt`, `http`, `mcp`, `docker`, `extensions`, `cypher`, `agents`); `version` (at most 40 characters) | `query` (the limit and filters applied), `version` (`verified`, a `warning` when `version` names another release, `retrieval`, which is `hybrid` or `full-text`, and a `retrieval_note` when the vector search was tried and did not answer), and `results`: ranked sections, each with `id` (`<page>#<anchor>`), `page` (`id`, `title`, `url`, `md_url`), `heading`, `anchor`, `url`, `snippet`, `score`, and, for a hybrid search, `ranks` (`vector`, `fulltext`). A `hint` is added when nothing matched |
| `get_page` | `slug` (a page id such as `get-started/install`) or `url` (the page URL, its `.md` URL, its `/index.md` URL or `relate-docs://page/<id>`; a `#fragment` selects a section), one of the two required; `heading` (an anchor, `#anchor` or the heading text, case-insensitive); `expand` (boolean); `version` | `page` (`id`, `title`, `url`, `md_url`, `description`, `type`, `status`), `section` (`anchor`, `heading`, `url`, or null), `form`, `version`, `prerequisites`, `related`, `terms` (`id`, `url`), `sections` (the page's anchors), `truncated` and `tokens_estimate`; the markdown itself is `content[1]` |
| `explain_error` | At least one of `code` (the error object's code, an entry id or a Neo4j code, matched exactly and case-insensitively; all digits match a CLI exit code; a negative integer matches a JSON-RPC code), `kind`, `gql_status`, `message` (matched against the recorded message patterns, whole-pattern matches first); several fields combine with AND | `page` ([Errors](/docs/reference/errors)), `matched_on`, `total`, `errors` (each entry's `id`, `surface`, `code`, `kind`, `gql_status`, `neo4j_code`, `exit_code`, `jsonrpc_code`, `http_status`, `python_class`, `retryable`, `message`, `cause`, `remedy`, `note`, its `url` at `https://relatedb.ai/docs/reference/errors/#<id>`, and `pages`: the errors page first, then every page that links to the entry), `notifications` for a GQLSTATUS, and a `hint` when nothing matched |
| `validate_cypher` | `statement` (required: one Cypher statement, under 8 KiB of UTF-8, not starting with `EXPLAIN` or `PROFILE`); `parameters` (a JSON object, under 8 KiB) | `ok`; with `ok: true`, `plan` (the operator table: Operator, Id, Details) and `notifications` (each `gql_status`, `code`, `severity`, `category`, `title`, `description`, `remedy`, `url` at its [Errors](/docs/reference/errors) entry, `empty_store: true` on an unknown label, relationship type or property key, and `differences` when it is a row of [Differences from Neo4j](/docs/reference/cypher/differences-from-neo4j)); over the 96 KiB text cap, `plan_truncated: true` when the plan was cut at a line, and `notifications_total` and `notifications_omitted` when notifications were left out from the end; with `ok: false`, `error` (`code`, `kind`, `line`, `column`, `message`, `gql_status`, `retryable`, `remedy`, `url`, `entry`) and `differences` (`feature`, `write_instead`, `url`) or null. Also `page` (Errors), `differences_page`, `engine` and `version` |
| `discover_capabilities` | `intent` (required, 1 to 300 characters); `requirements` (up to 10 strings: a surface, or words every entry must contain); `language` (a surface, as for `search_docs`); `limit` (1 to 20, default 5) | `page` ([Problems relate solves](/docs/concepts/problems-relate-solves)), `source` (`/docs/capabilities.json`), `note`, `query`, `total`, and `results`: each entry's `id`, `title`, `problem`, `capability`, `match` (`phrase` or `words`), `score`, `schema` (the data model diagram's `url` and `title`, or null), `urls` (`page`, `guides`, `integrations`, `recipes`, `reference`), `verify` (`ref`, `kind`, `url`, or null where no recorded run verifies the entry) and `surfaces`. A `hint` is added when nothing matched |

`search_docs` runs one fixed statement over the docs graph's full-text index `docs`, which covers the heading and text of every section of every authored page. The generated pages, [Glossary](/docs/reference/glossary), [Changelog](/docs/reference/changelog) and [Hosted docs MCP usage](/docs/reference/server/docs-mcp-usage), are not in the docs graph yet, so a search never returns them; `get_page` reads them, and the `search_docs` description says so. The words in `query` are bound as a parameter, never spliced into the statement. Common words (`the`, `how`, `from` and the like) are left out of the query unless nothing else is left. The index returns its 200 best sections, and the server ranks those: ten times the share of the query's words that appear in a section's heading, plus the index score divided by log2(2 + the section's length in characters), so the section a heading names comes before a long section that mentions the words in passing. `score` is that rank. A search hit's `anchor` is what `get_page` takes as `heading`.

When Workers AI answers, `search_docs` is a hybrid search. The query is embedded with `@cf/baai/bge-small-en-v1.5` and cls pooling, the model and pooling the section vectors were computed with, and a second fixed statement asks the docs graph's vector index `docs_vector` for the nearest sections. Each list's ten best sections (or `limit`, when larger), the vector list by similarity and the full-text list in the ranking above, are fused by reciprocal rank: a section earns 1 / (60 + its rank) from each list it is in, and `score` is the sum. `version.retrieval` is `hybrid`. When the model or the vector search fails, as every call to the model does under `wrangler dev --local`, the search is the full-text one alone, `version.retrieval` is `full-text`, and `version.retrieval_note` says the vector search did not answer. A Worker with no Workers AI binding never tries the vector search: `version.retrieval` is `full-text`, with no note. The section vectors load into the isolate's engine on the first hybrid search, so an isolate that answers only full-text searches never loads them.

`validate_cypher` sends `EXPLAIN` and the statement to a new WebAssembly instance of the engine with an empty in-memory store, created for that call and dropped after it, never the instance that holds the docs graph. The statement is planned and not run. A statement that already starts with `EXPLAIN` or `PROFILE`, after any comments, is refused, and an answer without a plan is reported as `validate_failed`, never returned as a result. The engine runs one statement per call, so a second statement after a semicolon is a syntax error, and the answer reports it. The `line` and `column` count from 1 in the statement as sent; both are null when the engine's message points at no position, or when the line it echoes fits more than one place in the statement (a repeated line, or a run of the same characters), so a position is never a guess. The `error.url` is the most specific [Errors](/docs/reference/errors) entry whose message pattern matches, or the general entry for the error's kind. A mistake that is a row of the [Differences from Neo4j](/docs/reference/cypher/differences-from-neo4j#differences) table cites that row, at its example's anchor where the page runs one. The store is empty, so every label, relationship type and property key is unknown to it: those warnings carry `empty_store: true` and say nothing about the caller's graph. If the engine instance traps, it is discarded, the answer is `validate_failed`, and the next call gets a new one.

`discover_capabilities` ranks the entries of the capability catalog by how well `intent` matches each entry's example intents and problem statement: an intent or the problem as a phrase first, then the share of the intent's words they hold, then the share in the capability and title. An entry is returned when a phrase matches or at least half of the intent's words are among its intents and problem, or among all of its text. `requirements` keep only the entries that meet every one, by naming one of the entry's surfaces or by all its words being in the entry's text; `language` keeps the entries whose surfaces include it. An empty list means the catalog has no entry for the intent, not that relate cannot do it.

`get_page` answers in one of three forms:

| `form` | When | The markdown in `content[1]` |
| --- | --- | --- |
| `opening` | No `heading`, no `expand` | The twin's frontmatter, H1, description, version line and the text before the first section, plus `sections` listing every anchor |
| `section` | `heading` given, or a `#fragment` in `url` | The frontmatter, then the twin's own bytes from that heading to the next heading at the same or a higher level (an H2 includes its H3s), then a `Terms used on this page` section with the page's terms that subtree uses (a glossary link or the term as a word), at most five, then a line `Full page: <url> (markdown: <md url>)`. The same bytes as the page's URL with `?section=<anchor>` and `Accept: text/markdown` |
| `page` | `expand: true` | The whole twin, byte for byte the file at `/docs/<id>.md` |

Tool errors are results with `isError: true` and the same `kind` and `note`, plus `error` (`code`, `message`):

| `error.code` | When | Also returned |
| --- | --- | --- |
| `page_not_found` | No published page has that id or URL | `suggestions` (up to five pages whose id or title shares a word with the request) and `index` (the `llms.txt` URL) |
| `heading_not_found` | The page has no section with that anchor or heading | `sections` (the page's anchors) |
| `engine_unavailable` | The engine instance in this isolate failed; lasts until Cloudflare replaces the isolate | None; `get_page`, `explain_error` and the resources keep working |
| `search_failed` | The search statement failed | None |
| `read_failed` | `get_page` failed to read a page it lists | None; the page's twin at its URL plus `.md` |
| `statement_too_large`, `parameters_too_large` | `validate_cypher`'s statement, or its parameters as JSON, is 8 KiB (8,192 bytes) or more | `limits` (`statement_bytes`, `parameters_bytes`) |
| `explain_prefix` | `validate_cypher`'s statement already starts with `EXPLAIN` or `PROFILE` | `limits` |
| `empty_statement` | The statement holds only whitespace or comments | `limits` |
| `validate_failed` | The engine instance for `validate_cypher` trapped, threw, or answered without a plan, or the answer does not fit the 96 KiB text cap even with the plan cut and every notification left out; the instance is discarded | `page`, `differences_page` |

Input that fails a tool's schema returns an `isError` result whose text starts with `Input validation error:`; `validate_cypher` parameters that are not a JSON object (a string, an array, `null`) are such input. A tool name the server does not have, such as `read_cypher`, is the JSON-RPC error `-32602` with the message `Tool <name> not found`.

A resource template, `relate-docs://skill/{+path}`, listed once per file | `text/markdown` |

| `relate-docs://capabilities` | The capability catalog, the same bytes as `https://relatedb.ai/docs/capabilities.json` | `application/json` |

A resource template, `relate-docs://example/{recipe}/{cell}`, listed once per cell. The cells of a recipe run in order, so a cell's result assumes the cells before it ran | `application/json` |

A URI that names no resource is the JSON-RPC error `-32602`, with the URI in `data.uri`.

## Prompts

| Prompt | Arguments | Returns |
| --- | --- | --- |
| `onboard` | None | One `user` message: a framing paragraph, then, verbatim, the sections of [Connect your agent to relate](/docs/get-started/agent-quickstart) that install a pinned relate, check the output format, install the skill, read the briefing and add relate to an `AGENTS.md` |
| `text-to-cypher` | `intent` (required, up to 2,000 characters); `schema` (optional, up to 32 KiB) | One `user` message: the intent; the schema, or where to get one on the user's own relate (the `get_schema` tool of `relate serve --mcp`, or the `db.schema` procedures, with the store opened `--read-only`); the table of [Differences from Neo4j](/docs/reference/cypher/differences-from-neo4j#differences), verbatim; and the steps: write the statement, check it with `validate_cypher`, repair it from the error or the notifications, and reply with the final statement |

The prompts are the one place the server's own text addresses an agent. A host sends one only when its user picks it, and `text-to-cypher` closes with the line that the table and every `validate_cypher` result are reference text, not instructions. Resources and tool results quote published files: the skill resource and the steps of how-to and tutorial pages are written to their reader, and the server serves them as reference text, with no authority over the receiving agent's task.

## Limits

Every row is a limit. The numbers are also in the plain-text answer to a `GET https://relatedb.ai/mcp` and in the `data` of every HTTP 429.

| Limit | Value | Over the limit |
| --- | --- | --- |
| Requests per IP address | 20 per 10 seconds, counting every request to `/mcp` other than the plain-text `GET` and an `OPTIONS` preflight, a malformed or oversized `POST` included (it counts before its body is read), and every `GET /healthz` | HTTP 429, JSON-RPC `-32010` `Rate limited`, `Retry-After` |
| Cost budget per IP address and tool | 120 units per 60 seconds for each tool: `search_docs` and `validate_cypher` cost 3 units, so 40 calls of each a minute; `get_page`, `explain_error`, `discover_capabilities`, `resources/read` and `prompts/get` cost 1. Other methods (`initialize`, `tools/list`, `resources/list`) cost nothing but count toward the request limit. Deployed, a call's units are spent one at a time, so a refused 3-unit call may already have spent part of its cost, and in a batch the calls before a refused one keep what they spent | HTTP 429, JSON-RPC `-32011` `Tool cost budget exhausted`, `Retry-After` |
| Request body | 64 KiB (65,536 bytes of UTF-8, not characters). A larger `Content-Length` is refused before the body is read, and a body sent without one is read only up to the cap | HTTP 413, JSON-RPC `-32012` `Request too large`, with `data.max_bytes` |
| Messages per request | 10: a JSON-RPC batch of more than 10 messages is refused before any of its calls spends from the cost budget. With the text cap, one response carries at most 10 capped results. The MCP revision of 2025-06-18 has no batches, so a client on it sends one message per request | HTTP 400, JSON-RPC `-32600` `Batch too large`, with `data.max_messages` |
| Text per tool result or resource | 96 KiB | The text is cut at a line and ends with a line naming the URL of the whole text; `get_page` sets `truncated: true`. A `validate_cypher` plan is cut to at most half the cap and ends with a line saying so (`plan_truncated: true`), and notifications that do not fit are left out from the end (`notifications_omitted`); a plan's Details cell is cut at 200 characters, ending in `…` |
| `search_docs` results | 20 at most, 5 by default | A `limit` greater than 20 fails the schema |
| `search_docs` candidates | The index returns the 200 best-matching sections; a `section` or `surface` filter applies to those, and the ranking chooses among them | A matching section the index ranks below 200 is not returned |
| `explain_error` matches | 10 entries at most; `total` counts every match | The rest are left out |
| `discover_capabilities` results | 20 at most, 5 by default; `total` counts every match | A `limit` greater than 20 fails the schema |
| `validate_cypher` statement and parameters | Each under 8 KiB (8,192 bytes of UTF-8); one statement; no `EXPLAIN` or `PROFILE` prefix | The tool errors `statement_too_large`, `parameters_too_large` and `explain_prefix` |
| `search_docs` hybrid lists | The vector and full-text lists each contribute their 10 best sections, or `limit` when larger | A section ranked lower than that in both lists is not returned by a hybrid search |
| Glossary terms per `get_page` section | 5 | `terms_omitted` says how many were left out |
| Input lengths | `query` 200 characters, `message` 2,000, `slug` 200, `url` 300, `code` and `kind` 100, `gql_status` 10, `version` 40, `intent` 300 (a prompt's 2,000), a requirement 100, a prompt's `schema` 32 KiB | An `Input validation error` result |

A 429 carries `Retry-After` in seconds, `RateLimit-Policy: "ip";q=20;w=10, "tool-cost";q=120;w=60`, and `data` with `retry_after`, `limits` (the limits in words) and `policy`. Deployed, the counters are kept by Cloudflare's rate limiting service, which counts per Cloudflare location in windows aligned to the clock and reports no reset time, so `Retry-After` is the window length, 10 or 60 seconds: an upper bound on the wait. Without that service, the Worker keeps the same numbers in a fixed window per isolate and gives the exact wait. `GET /healthz` says which limiter is in use.

Other JSON-RPC errors: `-32700` parse error (HTTP 400), `-32600` a batch of more than 10 messages (HTTP 400), `-32601` method not found, `-32603` internal error (HTTP 500).

## Threat model

The model covers what the server holds, what a caller can make it do, and what a result means.

| Concern | How the server handles it |
| --- | --- |
| What it holds | Only what the site already publishes: the docs pages, the errors data, the agent skill and the five task skills, the release list, the capability catalog, the cookbook cells with their recorded results, and the section vectors. No user data, no credentials, no secrets. Nothing a request sends is kept beyond the request |
| Writes | No write path. The statements run on the docs graph are fixed: the `search_docs` reads, with the caller's words or the query's vector bound as a parameter, and the one statement that loads the section vectors. The docs graph lives in the isolate's memory and is rebuilt from `/docs/graph.cypher` on each new isolate |
| A caller's Cypher | Only `validate_cypher` takes a statement, and it never reaches the docs graph: each call plans it with `EXPLAIN` on its own new engine instance with an empty in-memory store, dropped after the call. A statement with its own `EXPLAIN` or `PROFILE` is refused, the engine runs one statement per call, and an answer without a plan is a failure, not a result. Statement and parameters are each capped under 8 KiB, and a call costs 3 units of the budget. A statement that traps the engine discards only that call's instance; the instance's console is silent, so an engine panic's text never reaches the log |
| The read-only open | The WASM build cannot open a read-only in-memory store with content in it: a read-only in-memory store refuses every write, the load included, and the WASM cannot open a `.rl` file or a snapshot. So the graph is loaded into a writable in-memory store, and the fence is that no request can send a statement. A way to freeze a loaded store, or to open a snapshot read-only, is an upstream request |
| Free Cypher | Not offered. The WASM engine has no statement deadline, and one isolate serves many requests in turn, so one runaway statement (an unbounded traversal, say) would hold that isolate until Cloudflare's CPU limit stops it and stall every request queued behind it. A Cypher tool over the docs graph, `query_docs_graph`, ships only once the engine exposes a deadline. `validate_cypher` plans without running, on an empty store |
| Query embeddings | With Workers AI, the text of a `search_docs` query is sent to Cloudflare Workers AI to compute its vector. The Worker does not log it; what Workers AI records about a request is set by Cloudflare's terms for the account and is to be published here at launch |
| A failed engine | If the engine instance fails, `search_docs` answers `engine_unavailable` until Cloudflare replaces the isolate; `get_page`, `explain_error` and the resources read the bundled pages and keep working |
| Volume | The per-IP request limit and the per-tool cost budget of [Limits](#limits), a 64 KiB request cap, and a 96 KiB cap on the text of each result. A JSON-RPC batch counts once against the request limit, carries at most 10 messages, and each call in it spends from the cost budget, so one request returns at most 10 capped results. The budget exists because cloud agent harnesses share outgoing addresses: one per-IP number would be too strict for many agents behind one address and too loose for one agent repeating a search |
| Cross-origin use | CORS (cross-origin resource sharing) allows every origin (`*`), with no cookies and no credentials, and the server does not check `Origin`. A page on any website can call it and read only what the docs already publish |
| Accounts | None. There is nothing to sign in to and nothing to take over |

**What a result means.** A result is a quotation of the published documentation at the verified version, with the page it came from. It is reference text, not instructions: it carries no authority over the task of the agent that receives it, and it is never phrased as an order to that agent. A result says what the docs say about relate 0.16.1; it does not show what the relate a client has installed does. `relate --version` and running the statement show that, and `search_docs` and `get_page` add a `version.warning` when the `version` given names another release. The only text the server itself writes to an agent is in the `onboard` and `text-to-cypher` prompts, sent when a host's user picks one.

## What is logged

The Worker writes one JSON line per request to `/mcp` or `/healthz`, with `evt: "docs-mcp"` and these fields:

| Field | Holds |
| --- | --- |
| `path`, `http` | The path and the HTTP method |
| `rpc` | The JSON-RPC methods in the request, from a fixed list of known names; anything else is `other`, and a client's response is `response` |
| `tool` | The tool called, if it is one of the five; any other name is `unknown` |
| `ua` | The client family from the `User-Agent` header, from a fixed list (such as `claude-code`, `cursor`, `codex`, `curl`); anything else is `other`, and no header is `none` |
| `status`, `ms` | The HTTP status and the duration in milliseconds |
| `zero_results` | For `search_docs`, `explain_error` and `discover_capabilities`: whether nothing matched |
| `tool_error`, `limited`, `rpc_error` | The tool error code, which limit was hit (`ip` or `tool-cost`), the JSON-RPC error code, when they apply |

Never logged: the query text, the statement sent to `validate_cypher`, the page or heading asked for, any argument, an error message, an IP address, or the whole `User-Agent` string. An exception the Worker does not expect adds one line with `evt: "docs-mcp-error"`, the path and the exception's type, never its message. Cloudflare's invocation log for each request, which carries Cloudflare's own request metadata, is turned off in the Worker's configuration. The rate limiter keys its counters by the client's IP address; the address is not written to the log. How long these lines are kept, and what Cloudflare itself records about each request and for how long, depend on the Cloudflare account, which does not exist yet: both are to be published here at launch.

## When the server is unavailable

No uptime commitment is published. The server reads the same files the site serves, and those keep answering when the Worker is down or a client is over its limit:

| Instead of | Read |
| --- | --- |
| `search_docs` | The docs index, `https://relatedb.ai/docs/llms.txt`, and every page at once, `https://relatedb.ai/docs/llms-full.txt` |
| `get_page` | The page's twin: its URL plus `.md`, such as `https://relatedb.ai/docs/reference/errors.md` |
| `explain_error` | [Errors](/docs/reference/errors), one entry per anchor |
| `validate_cypher` | `EXPLAIN` before the statement, on a local relate: the plan and the notifications with their remedies, or the error |
| `discover_capabilities` | [Problems relate solves](/docs/concepts/problems-relate-solves), and the same entries at `https://relatedb.ai/docs/capabilities.json` |
| Any of them, offline | [The local equivalent](#the-local-equivalent) |

## The local equivalent

The docs graph the server searches is also to be published as a relate store, `https://relatedb.ai/docs/relate-docs.rl`, built from the same seed by the relate CLI, with its SHA-256 beside it at `https://relatedb.ai/docs/relate-docs.rl.sha256`. Both URLs are launch-day targets: the store is built and served once the deploy workflows install relate. `--load` into the default :term[in-memory store]{id=in-memory-store} opens it :term[read-only]{id=read-only}, and the search runs offline once the file is downloaded.

The checked path is to download the store, compare its SHA-256 with the published value, and load the local copy. In this block, `<sha256>` is the value in `relate-docs.rl.sha256`, and the search runs only when it matches; on macOS, `shasum -a 256 --strict -c -` stands in for `sha256sum --strict -c -`:

```bash
curl -sSfLO https://relatedb.ai/docs/relate-docs.rl
echo "<sha256>  relate-docs.rl" | sha256sum --strict -c - && relate --load ./relate-docs.rl --mode envelope "MATCH (s:Section) SEARCH s IN (FULLTEXT INDEX docs FOR 'exit code' LIMIT 5) SCORE AS score RETURN s.page AS page, s.heading AS heading, s.url AS url, score"
```

The same store served over MCP on the agent's own machine has relate's own tools, `read_cypher` and `get_schema`, not this server's five, so any read over the docs graph is allowed there. A relative path resolves against the directory the host starts the server in:

```bash
claude mcp add relate-docs-local -- relate serve --mcp stdio --database :memory: --load <absolute-path>/relate-docs.rl --read-only
```

## Examples

Adding the server to Claude Code, for the current project:

{/* docs-check-ignore trust-read-only */}
```bash
claude mcp add --transport http relate-docs https://relatedb.ai/mcp
```

The same entry in a project's `.mcp.json`, which `claude mcp add --scope project` writes:

{/* docs-check-ignore trust-read-only */}
```json title=".mcp.json"
{
  "mcpServers": {
    "relate-docs": {
      "type": "http",
      "url": "https://relatedb.ai/mcp"
    }
  }
}
```

Neither entry carries `--read-only`: the server opens no store of yours and has no write path. [Connect over MCP](/docs/guides/agents/connect-over-mcp#add-the-relate-docs-server) has the entry for each other host.

```bash
curl -s https://relatedb.ai/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"0"}}}'
```
