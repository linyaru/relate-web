Social Network Tutorial

In this tutorial you'll model a small social network and use graph traversals to answer questions that would be difficult with a relational database.

Setup​

./cypherlite ./social

Parquet snapshot by default. For graph.json checkpoints, use a new directory: ./cypherlite --snapshot-format json ./social-json.

Build the network​

Create people:

CREATE (:Person {name: 'Alice', city: 'NYC', age: 30});
CREATE (:Person {name: 'Bob', city: 'NYC', age: 28});
CREATE (:Person {name: 'Charlie', city: 'LA', age: 35});
CREATE (:Person {name: 'Diana', city: 'LA', age: 32});
CREATE (:Person {name: 'Eve', city: 'Chicago', age: 27});
CREATE (:Person {name: 'Frank', city: 'Chicago', age: 40});

Create friendships:

MATCH (a:Person {name: 'Alice'}), (b:Person {name: 'Bob'}) CREATE (a)-[:FRIENDS]->(b);
MATCH (a:Person {name: 'Alice'}), (c:Person {name: 'Charlie'}) CREATE (a)-[:FRIENDS]->(c);
MATCH (b:Person {name: 'Bob'}), (d:Person {name: 'Diana'}) CREATE (b)-[:FRIENDS]->(d);
MATCH (c:Person {name: 'Charlie'}), (d:Person {name: 'Diana'}) CREATE (c)-[:FRIENDS]->(d);
MATCH (d:Person {name: 'Diana'}), (e:Person {name: 'Eve'}) CREATE (d)-[:FRIENDS]->(e);
MATCH (e:Person {name: 'Eve'}), (f:Person {name: 'Frank'}) CREATE (e)-[:FRIENDS]->(f);

Query: Direct friends​

MATCH (alice:Person {name: 'Alice'})-[:FRIENDS]-(friend)
RETURN friend.name, friend.city;

We use an undirected pattern [:FRIENDS]- so we find friends regardless of who initiated the relationship.

Query: Friends of friends​

Find people who are two hops away from Alice:

MATCH (alice:Person {name: 'Alice'})-[:FRIENDS]-()-[:FRIENDS]-(fof)
WHERE fof.name <> 'Alice'
RETURN DISTINCT fof.name, fof.city;

Query: Variable-length paths​

Find everyone within 3 hops of Alice:

MATCH (alice:Person {name: 'Alice'})-[:FRIENDS*1..3]-(connected)
RETURN DISTINCT connected.name, connected.city;

Query: Friends in the same city​

MATCH (p:Person)-[:FRIENDS]-(friend)
WHERE p.city = friend.city
RETURN p.name, friend.name, p.city;

Query: Most connected people​

MATCH (p:Person)-[:FRIENDS]-(friend)
RETURN p.name, count(friend) AS friendCount
ORDER BY friendCount DESC;

Query: Recommend friends​

Find people Alice doesn't know who are friends-of-friends:

MATCH (alice:Person {name: 'Alice'})-[:FRIENDS]-(friend)-[:FRIENDS]-(recommended)
WHERE NOT (alice)-[:FRIENDS]-(recommended)
  AND recommended.name <> 'Alice'
RETURN DISTINCT recommended.name, count(friend) AS mutualFriends
ORDER BY mutualFriends DESC;

Query: Shortest path between people​

Find the shortest connection path between Alice and Frank:

MATCH (alice:Person {name: 'Alice'}), (frank:Person {name: 'Frank'})
RETURN shortestPath((alice)-[:FRIENDS*..10]->(frank)) AS path;

The shortestPath() function uses breadth-first search to find the connection with the fewest hops.

Query: Check if connection exists​

Use EXISTS to filter people who have a direct or indirect path to Eve:

MATCH (p:Person)
WHERE EXISTS { MATCH (p)-[:FRIENDS*1..3]->(:Person {name: 'Eve'}) }
RETURN p.name AS connectedToEve;

What you learned​

  • Undirected relationship patterns for bidirectional traversal
  • Variable-length paths with *1..3 syntax
  • Friend-of-friend traversals
  • DISTINCT to remove duplicates
  • Using WHERE NOT with patterns for negative filtering
  • shortestPath() for finding shortest connections between people
  • EXISTS subqueries for checking pattern existence
  • Aggregation for ranking
