CLI Flags Reference

Synopsis​

cypherlite [OPTIONS] [DATABASE] [QUERY]

Arguments​

ArgumentDescriptionDefault
DATABASEPath to the database directory (WAL + snapshot), a .cl bundle file, or :memory::memory:
QUERYCypher query to execute in non-interactive mode(none — starts interactive shell)

Options​

FlagDescription
-jsonOutput results as JSON
-csvOutput results as CSV
-markdownOutput results as Markdown
-noheaderDisable column headers
-mode MODESet output mode (table, csv, json, jsonl, markdown, cypher)
--param N=VBind a Cypher parameter (repeatable)
--snapshot-format parquet|jsonSnapshot codec for an empty directory (default parquet). Stored in manifest.json; do not mix with the other format. CYPHERLITE_SNAPSHOT_FORMAT for empty URIs.
--wal-dir DIRWAL directory (default <DATABASE>/wal)
--checkpoint-interval-secs NTimed checkpoint period; 0 disables. Persistent URIs only
--memory-limit SIZELive graph + index cap (mb/mib/gb/gib)
-c, --command CYPHEROne-shot query (same as positional QUERY)
-versionShow version and exit

All flags also accept a double-dash form (--json, --csv, etc.).

Lifecycle commands​

Exit-after lifecycle verbs are positional commands, recognized only as the first argument:

CommandDescription
cypherlite skill install [--agent NAME]Install the agent-skill bundle (default: all detected agents)
cypherlite skill remove [--agent NAME]Remove the agent-skill bundle
cypherlite upgrade [--yes] [--check]Self-update to the latest GitHub release. --check is a read-only current-vs-latest report; --yes auto-accepts the post-upgrade skill-bundle refresh prompt
cypherlite update [--yes] [--check]Alias of upgrade
cypherlite telemetry on|off|statusManage anonymous usage metrics (below)
cypherlite pull [--from FILE] --query Q [--param N=V] DATABASEPull a Neo4j/Aura subgraph over HTTP Query API v2 into DATABASE (union/upsert on source elementId)

Database paths literally named skill, upgrade, update, telemetry, or pull stay reachable via a ./ prefix (cypherlite ./skill) or after -- (cypherlite -- skill). upgrade sends Authorization: Bearer $GITHUB_TOKEN on release downloads while the repository is internal.

Anonymous usage metrics​

The CLI reports anonymous usage metrics (command shapes, feature flags, an anonymous install id, and a coarse environment tag — never query text, paths, or data). Collection defaults to on and has a layered opt-out, checked in this order:

  1. DO_NOT_TRACK=1 (the consoledonottrack convention)
  2. CYPHERLITE_TELEMETRY (0 / false / off disables)
  3. cypherlite telemetry off, persisted in <config>/cypherlite/config.json ($XDG_CONFIG_HOME/cypherlite/ when $XDG_CONFIG_HOME is set, otherwise ~/.config/cypherlite/)
cypherlite telemetry status   # e.g. "enabled (default)" / "disabled (DO_NOT_TRACK)"
cypherlite telemetry off      # persist the opt-out; prints the config path

status prints <enabled|disabled> (<layer>), where the deciding layer is default, config file, CYPHERLITE_TELEMETRY, or DO_NOT_TRACK. Only the standalone cypherlite CLI collects metrics; the embedded Rust/Python/WASM APIs do not. A one-time notice on first run explains this, and telemetry failures are swallowed — they never affect the exit code or output.

Modes of operation​

CypherLite operates in one of three modes, determined automatically:

Interactive mode​

When no QUERY argument is provided and stdin is a terminal, CypherLite starts the interactive REPL shell.

# In-memory database
cypherlite

# Persistent database directory (Parquet snapshot + WAL)
cypherlite ./friends

The shell displays a cypher> prompt. Statements end with ;. Enter .help for .begin / .commit / .rollback / .quit. On a TTY the prompt supports readline-style editing (arrow keys, Home/End) and in-session history (ADR-0073).

Query mode​

When a QUERY argument is provided, CypherLite executes it and exits. If the query fails, the process exits with a non-zero status (see Exit codes).

cypherlite ./friends "MATCH (p:Person) RETURN p.name"

Pipe mode​

When stdin is not a terminal (i.e., input is being piped), CypherLite reads and executes all statements from stdin. Statement splitting is comment- and string-aware, so a ; inside a string literal or a // / /* */ comment does not split a statement.

cypherlite ./friends < setup.cypher

echo "MATCH (n) RETURN count(*)" | cypherlite ./friends

In pipe mode a failing statement stops the batch and the process exits non-zero (see Exit codes).

Output format flags​

Output format flags set the mode before executing the query. Only one format flag should be used at a time.

-json​

Outputs results as a JSON array. Each row is a JSON object with column names as keys.

$ cypherlite ./friends -json "MATCH (p:Person) RETURN p.name, p.age"
[
  {"p.name": "Alice", "p.age": 30},
  {"p.name": "Bob", "p.age": 28}
]

-csv​

Outputs results as comma-separated values with a header row.

$ cypherlite ./friends -csv "MATCH (p:Person) RETURN p.name, p.age"
p.name,p.age
Alice,30
Bob,28

-markdown​

Outputs results as a Markdown table.

$ cypherlite ./friends -markdown "MATCH (p:Person) RETURN p.name, p.age"
| p.name | p.age |
|--------|-------|
| Alice  | 30    |
| Bob    | 28    |

-noheader​

Suppresses column headers. Can be combined with any output format.

$ cypherlite ./friends -csv -noheader "MATCH (p:Person) RETURN p.name"
Alice
Bob

-version​

Prints the version string and exits immediately.

$ cypherlite -version
CypherLite v0.6.1

Examples​

# Start interactive shell with in-memory database
cypherlite

# Open or create a persistent directory (default parquet snapshot + WAL)
cypherlite ./friends

# Same directory, human-readable graph.json checkpoints
cypherlite --snapshot-format json ./friends-json

# Run a single query
cypherlite ./friends "MATCH (p:Person) RETURN p.name ORDER BY p.name"

# JSON output piped to jq
cypherlite -json ./friends "MATCH (p:Person) RETURN p" | jq '.[].["p.name"]'

# Execute a script file
cypherlite ./friends < schema.cypher

# CSV export without headers
cypherlite -csv -noheader ./friends "MATCH (p:Person) RETURN p.name, p.age" > people.csv

# Chain with shell pipes
echo "RETURN 1 + 2 AS result;" | cypherlite :memory:

Snapshot codecs (CypherLite)​

The product CLI writes a directory: WAL plus one snapshot codec (ADR-0050). Do not mix Parquet shards and graph.json in the same directory.

# Empty directory → parquet (default)
cypherlite ./friends

# Empty directory → CypherLite GraphData in graph.json
cypherlite --snapshot-format json ./friends-json
# equivalent: CYPHERLITE_SNAPSHOT_FORMAT=json cypherlite ./friends-json

Import a GraphData JSON file by copying it to graph.json in an empty directory, then opening with --snapshot-format json.

Exit codes​

CodeMeaning
0Success (--help and --version also exit 0)
1Runtime failure: database open failure, or a failed statement in query/pipe mode
2Usage error: unknown flag, invalid/missing --mode value

In query mode and pipe mode, a statement that errors makes the process exit 1. In pipe mode the run stops at the first failure. Prior durable state is always flushed before a non-zero exit. The interactive shell never fails the process for a query error — it reports the error and returns to the prompt.

Full contract: docs/api/cli/spec.md.
