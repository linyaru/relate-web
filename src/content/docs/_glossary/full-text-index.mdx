A full-text index splits the strings of the properties it covers into lowercase alphanumeric words and finds the entities that contain any word of a query, ignoring case; `AND`, `OR` and `NOT` in capitals combine words. There is no stemming: `graphs` does not match `graph`. The score is BM25, as in Neo4j: a word few entities hold counts for more, and a match in a short text counts for more than one in a long text.

```cypher
CREATE FULLTEXT INDEX doc_text IF NOT EXISTS FOR (d:Doc) ON EACH [d.title, d.body]
```

The :term[SEARCH clause]{id=search} queries it with a string and a required `LIMIT`, and accepts `SKIP` and `WITH ANALYZER`; the analyzer applies to the query string only, and `english` stems its words and drops English stop words. `SHOW INDEXES` lists it with the type `FULLTEXT`. A full-text and a vector search can be fused into one ranking with `COMBINE`, a preview feature.
