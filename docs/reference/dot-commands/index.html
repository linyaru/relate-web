Dot-Commands Reference

The interactive shell implements exactly seven dot-commands. Dot-commands are entered at the cypher> prompt and are line-based: they submit on Enter and do not require a trailing ; (a ; is tolerated). Any other command starting with . fails with Error: unknown command <name> (exit 1 in non-interactive mode).

On a TTY the prompt is a rustyline editor (ADR-0073): arrow keys, Home/End, and emacs bindings edit the current line, and up/down walk in-session history. There is no tab completion or persistent history file. Piped stdin stays a plain reader. Cypher statements submit on a terminating top-level ;; until then the continuation prompt ...> keeps reading. A blank line does not submit a pending statement. Ctrl-C clears the pending buffer and returns to cypher>.

Quick reference​

CommandDescription
.helpShow the command summary
.quit / .exitExit CypherLite
.beginBegin an explicit transaction
.commitCommit the open transaction (persists durably)
.rollbackRoll back the open transaction (discards changes)
.checkpointForce an immediate checkpoint (snapshot + WAL recycle)
.timer on|offToggle per-statement wall-clock timing (default off)

All seven commands work identically in the interactive shell and in piped stdin. In piped stdin the batch is fail-fast: the first failing statement stops the run and the process exits 1.

Shell commands​

.help​

Prints the command summary:

cypher> .help
  Cypher statement ending with ;
  .begin / .commit / .rollback / .checkpoint
  .timer on|off
  .quit

.quit / .exit​

Exits the process immediately with status 0 (bare exit / EXIT work too). If an explicit transaction is still open (.begin with no matching .commit), its uncommitted writes are simply discarded — they were never published to the graph or the WAL. Run .commit before exiting to persist them.

Transactions​

By default CypherLite runs in autocommit mode: each statement that mutates the graph commits durably on success (it is flushed to disk before the result returns). The .begin / .commit / .rollback commands group several statements into one durable unit instead. See Storage Engine for the durability model (WAL + snapshot codec + checkpoint).

These commands succeed silently — no confirmation is printed. Errors are reported on stderr.

.begin​

Begins an explicit transaction. Subsequent statements accumulate in the transaction and are not written to disk until you .commit. A second .begin while a transaction is already open is an error (semantic error: already in a transaction).

cypher> .begin
cypher> CREATE (:Person {name: 'Alice'});
cypher> CREATE (:Person {name: 'Bob'});

.commit​

Commits the open transaction, durably persisting all of its statements as a single unit. With no open transaction it errors (semantic error: no transaction). A statement that fails inside a transaction rolls back only its own partial writes, but it also poisons the transaction: every later statement and .commit then error semantic error: transaction failed; rollback required until you .rollback.

.rollback​

Rolls back the open transaction, discarding every statement executed since .begin. With no open transaction it errors (semantic error: no transaction).

cypher> .begin
cypher> CREATE (:Scratch {tmp: true});
cypher> .rollback
cypher> MATCH (n:Scratch) RETURN count(n) AS c;
+---+
| c |
+---+
| 0 |
+---+

Storage commands​

.checkpoint​

Forces an immediate checkpoint: the snapshot codec rewrites its snapshot (parquet shards or graph.json) up to the current state and the WAL recycles the segments covered by it. Succeeds silently. On a :memory: database it succeeds without writing anything (there is no durable store).

cypher> .checkpoint
cypher>

Periodic automatic checkpoints are configured with --checkpoint-interval-secs; see Storage Engine for what a checkpoint writes.

Display commands​

.timer on|off​

Toggles per-statement wall-clock timing. Default is off (SQLite-style). When on, every successfully executed Cypher statement prints its wall-clock run time after the result, as Time: N.NNNms; the time covers execution plus result formatting. Entering .timer with anything but on or off prints Usage: .timer on|off and leaves the state unchanged.

cypher> .timer on
Timer: on
cypher> RETURN 1 AS x;
+---+
| x |
+---+
| 1 |
+---+
Time: 0.042ms
cypher> .timer off
Timer: off

Withdrawn commands (ADR-0058)​

The following legacy dot-commands were withdrawn with the interactive shell surface reduction (ADR-0058). Entering any of them fails with Error: unknown command <name>:

  • Output/formatting: .mode, .headers, .width, .output, .once, .bail — use the CLI's --mode / --json / --csv / --markdown / --noheader flags and shell redirection instead.
  • Introspection: .labels, .reltypes, .schema, .indexes, .constraints, .count, .databases, .version — use Cypher (UNWIND labels(n) AS l RETURN DISTINCT l, type(r), count(...)) or cypherlite --version.
  • Data management: .dump, .read, .backup, .restore, .import, .export — use piped stdin (cypherlite ./db < script.cypher), LOAD CSV, and output flags with redirection. For durable backup, copy the database directory after a .checkpoint (see Backup and Restore).
  • Multi-database: .open, .close, .attach, .detach, .use — the database is chosen once at startup (cypherlite [DATABASE]); one process operates on one graph (see Limitations).
  • Query analysis: .explain, .profile — not currently exposed in the shell.
  • Versioned storage: .compact, .versions, .checkout — Lance versioning was withdrawn with GraphStore (ADR-0052).
