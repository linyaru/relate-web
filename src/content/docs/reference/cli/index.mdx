`relate` is one binary with two kinds of run. A query run executes Cypher statements against one :term[store]{id=store} and prints their results; a command (`relate <command>`) does one job, such as copying a store or serving it, and exits. This page lists the invocation forms, every command the binary's `relate --help` prints, the query-run flags by family and the shell dot commands, with a link to the page that holds each detail.

## Synopsis

```text
relate [OPTIONS] [--database PATH] [QUERY]
relate <COMMAND> [ARGS]
relate query [STATEMENT] [--database PATH]
```

| Form | What runs |
| --- | --- |
| `relate [OPTIONS] [QUERY]` | The path-first query run. `QUERY` (or `-c`, `--command`) is one statement or a `;`-separated list. With no `QUERY`, a terminal opens the interactive shell; piped or redirected stdin prints the top-level help and exits 0. |
| `relate query [STATEMENT]` | The same query session as a command word. With no `STATEMENT`, it reads a script from stdin, or opens the interactive shell on a terminal. |
| `relate <COMMAND> [ARGS]` | A command: it does its job and exits. Each command takes its own flags, listed on the [flags page](/docs/reference/cli/flags#command-flags). |

`--database` (short form `-d`) names the store: a directory, a single-file `.rl` store, or `:memory:`, the default. The word `query` as the first positional is the command; a directory named `query` is `--database ./query`.

## Shell dot commands

A line that starts with a dot is a shell command, not Cypher. Dot commands work in the interactive shell and in a script piped to `relate query` (or to the path-first form), one per line, with no trailing `;`. `.help` prints the same set the table lists.

| Command | Effect | Fails with |
| --- | --- | --- |
| `.begin` | Opens an explicit transaction: later statements see its writes, and nothing is committed until `.commit` | `semantic error: already in a transaction` when one is open |
| `.commit` | Commits the open transaction | `semantic error: no transaction` when none is open |
| `.rollback` | Discards the open transaction's writes | `semantic error: no transaction` when none is open |
| `.checkpoint` | Writes a :term[checkpoint]{id=checkpoint} of a persistent store now; prints nothing | — |
| `.info` | Prints the store's metadata as a key/value table, the fields `relate info` prints; `:memory:` prints node and relationship counts and the index and constraint catalog | — |
| `.timer on`, `.timer off` | Prints `Timer: on` or `Timer: off`, and while on, a `Time: <n>ms (parse … / plan … / execute …)` line on stdout after each result | — (without an argument it prints `Usage: .timer on\|off`) |
| `.quit` | Ends the session; lines after it are not read | — |

Any other dot command fails with `Error: unknown command .<name>` (exit code 1). A session that ends with a transaction open, by `.quit` or at the end of a script, rolls it back, prints `Warning: exiting with an open transaction; rolling back uncommitted changes. Use .commit before exiting to persist them.` on stderr, and exits 1. In a script, a failed dot command stops the script with exit code 1, like a failed statement.

A transaction in a piped script, rolled back:

```bash verify
printf '.begin\nCREATE (:Note);\n.rollback\nMATCH (n:Note) RETURN count(n) AS notes;\n' | relate query --mode envelope
```

```text
{"columnTypes":[],"columns":[],"notifications":[],"rows":[],"truncated":false}
{"columnTypes":["INTEGER"],"columns":["notes"],"notifications":[],"rows":[{"notes":0}],"truncated":false}
```

## Examples

A one-statement query run on the default in-memory store, printed as an :term[envelope]{id=envelope}:

```bash verify
relate --mode envelope "RETURN 1 AS ok"
```

```text
{"columnTypes":["INTEGER"],"columns":["ok"],"notifications":[],"rows":[{"ok":1}],"truncated":false}
```

`relate query` with no statement reads a script from piped stdin, one envelope per statement:

```bash verify
printf 'RETURN 1 AS a;\nRETURN 2 AS b;\n' | relate query --mode envelope
```

```text
{"columnTypes":["INTEGER"],"columns":["a"],"notifications":[],"rows":[{"a":1}],"truncated":false}
{"columnTypes":["INTEGER"],"columns":["b"],"notifications":[],"rows":[{"b":2}],"truncated":false}
```

The version line names the release:

```bash verify
relate --version
```

```text
Relate v0.16.1
License: Apache 2.0 (binary)
```
