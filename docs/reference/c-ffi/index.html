C FFI Reference

The cypherlite-ffi crate exposes a small, C-compatible API for embedding CypherLite in any language with a C FFI (C, C++, and others). It is the foundation the JS/Java/Go clients are built on. The ABI is backed by cypherlite::Database. The same library exposes two handle models (ADR-0054): a bundled single-connection handle (cypherlite_open / cypherlite_execute, JSON envelope, one connection) and a tabular multi-connection API (cypherlite_database_open / cypherlite_connect / cypherlite_query) used by JS/Java/Go.

The crate builds as both a staticlib and a cdylib. The C header is committed at crates/cypherlite-ffi/include/cypherlite.h and can be regenerated from the Rust source with make gen-ffi-header (cbindgen). Query results cross the boundary as the canonical cypherlite_model::wire JSON encoding — the same value/stats shape every CypherLite surface emits.

Contracts​

Before the function list, four contracts govern every call. They are stated in the header comment and enforced in the implementation.

Memory ownership​

  • Strings returned by cypherlite_execute / cypherlite_execute_with_params and the *_result / transaction functions are owned by the caller and must be freed with cypherlite_free_string().
  • Handles from cypherlite_new / cypherlite_open must be freed with cypherlite_free().
  • The pointer from cypherlite_last_error() is owned by CypherLite (thread-local storage) and must not be freed.

Threading​

A CypherLiteHandle is not safe for concurrent use — there is no internal locking. All calls that share a handle must be serialized by the caller (one at a time). Distinct handles may be used from distinct threads. cypherlite_last_error() is backed by thread-local storage and reports only the most recent error recorded on the calling thread.

Panic safety and handle poisoning​

Every entry point catches Rust panics at the FFI boundary (an unwind crossing into C is undefined behavior); argument decoding happens inside the guard too. If a call panics, the handle is poisoned — it is not freed, but every subsequent call on it returns a defined error payload (an error JSON field, a 0 result, or NULL) instead of touching the possibly-inconsistent engine. The panic reason is retrievable from cypherlite_last_error(). Recover by freeing the handle with cypherlite_free() and opening a fresh one.

Error reporting (cypherlite_last_error)​

cypherlite_open() returns NULL on failure; call cypherlite_last_error() on the same thread immediately afterward to get the reason. The returned string remains valid only until the next FFI call on that thread records an error — copy it if you need to retain it.

Functions​

cypherlite-ffi exposes 15 extern "C" functions.

Lifecycle​

FunctionSignatureNotes
cypherlite_newCypherLiteHandle *cypherlite_new(void)New in-memory instance.
cypherlite_openCypherLiteHandle *cypherlite_open(const char *path)":memory:" for in-memory, or a CypherLite directory URI for WAL + snapshot persistence. Returns NULL on error (see cypherlite_last_error).
cypherlite_freevoid cypherlite_free(CypherLiteHandle *handle)Frees a handle. Safe to call with NULL.

Query execution​

FunctionSignatureNotes
cypherlite_executechar *cypherlite_execute(CypherLiteHandle *handle, const char *query)Runs a query; returns the wire-JSON envelope. Free with cypherlite_free_string.
cypherlite_execute_with_paramschar *cypherlite_execute_with_params(CypherLiteHandle *handle, const char *query, const char *params_json)params_json is a JSON object string, e.g. '{"name":"Alice","age":30}'.
cypherlite_free_stringvoid cypherlite_free_string(char *s)Frees a returned string. Safe to call with NULL.

The result JSON is the canonical wire envelope:

{"columns": [...], "rows": [...], "stats": {...}, "error": null}

Nodes, relationships, paths, points, geometries, and vectors are structured JSON; temporal values are ISO-8601 strings; stats carries all 11 mutation counters (snake_case, zeros included). On error:

{"columns": [], "rows": [], "stats": {}, "error": "<message>"}

Error reporting​

FunctionSignatureNotes
cypherlite_last_errorconst char *cypherlite_last_error(void)Most recent error on the calling thread, or NULL. Do not free.

Persistence​

FunctionSignatureNotes
cypherlite_flush_resultchar *cypherlite_flush_result(CypherLiteHandle *handle)Checkpoint the database and recycle eligible WAL; returns a JSON status reporting failure.
cypherlite_flushvoid cypherlite_flush(CypherLiteHandle *handle)Deprecated — forwards to cypherlite_flush_result and discards the status. Retained for ABI compatibility.
cypherlite_reset_resultchar *cypherlite_reset_result(CypherLiteHandle *handle)Reset an in-memory database to empty; returns a JSON status. Rejects active transactions and file-backed handles.
cypherlite_resetvoid cypherlite_reset(CypherLiteHandle *handle)Deprecated — forwards to cypherlite_reset_result and discards the status.

CypherLite is durable by default: an autocommit statement fsyncs its WAL record before cypherlite_execute returns. cypherlite_flush_result requests a checkpoint; it is not the commit durability boundary. See Storage Engine → Persistence model.

Transactions​

FunctionSignatureNotes
cypherlite_supports_transactionsuint8_t cypherlite_supports_transactions(CypherLiteHandle *handle)Returns 1 when the backend supports atomic transactions.
cypherlite_begin_transactionchar *cypherlite_begin_transaction(CypherLiteHandle *handle)Begin one transaction per handle.
cypherlite_commit_transactionchar *cypherlite_commit_transaction(CypherLiteHandle *handle)Durably commit the active transaction.
cypherlite_rollback_transactionchar *cypherlite_rollback_transaction(CypherLiteHandle *handle)Roll back the active transaction.

Transactions are single-level: exactly one active transaction per handle, nesting is rejected, and manual flush/reset cannot bypass an open boundary (see Limitations). Each of these returns a JSON status string that must be freed with cypherlite_free_string().

Example​

#include "cypherlite.h"
#include <stdio.h>

int main(void) {
    CypherLiteHandle *db = cypherlite_open(":memory:");
    if (db == NULL) {
        fprintf(stderr, "open failed: %s\n", cypherlite_last_error());
        return 1;
    }

    char *r1 = cypherlite_execute(db, "CREATE (:Person {name: 'Alice', age: 30})");
    cypherlite_free_string(r1);

    char *r2 = cypherlite_execute_with_params(
        db,
        "MATCH (p:Person) WHERE p.age >= $min RETURN p.name AS name",
        "{\"min\": 18}");
    printf("%s\n", r2);   /* {"columns":["name"],"rows":[{"name":"Alice"}],"stats":{...},"error":null} */
    cypherlite_free_string(r2);

    cypherlite_free(db);
    return 0;
}

Link against the static or dynamic library built by cargo build -p cypherlite-ffi (libcypherlite_ffi.a / .dylib / .so) and add the header directory to your include path.
