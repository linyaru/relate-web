This guide shows you how to get from an error to its fix. Find the message in the tables, follow the reference link for the error's cause and exit code, and follow the fix link for the steps. Every row points at a page; the [errors reference](/docs/reference/errors) holds the complete entry for each one.

## Prerequisites

- The error's text from stderr and the command's :term[exit code]{id=exit-code}.
- `relate` on your `PATH` ([Install relate](/docs/get-started/install)).
- To follow along, the shared example graph as `team.rl`:

```bash verify
cat > team.cypher <<'EOF'
CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
       (grace:Person {name: 'Grace', role: 'engineer'}),
       (noor:Person {name: 'Noor', role: 'maintainer'}),
       (relate:Project {name: 'relate', language: 'Rust'}),
       (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
       (ada)-[:WORKS_ON {since: 2024}]->(relate),
       (grace)-[:WORKS_ON {since: 2023}]->(relate),
       (grace)-[:WORKS_ON {since: 2022}]->(tck),
       (noor)-[:MAINTAINS]->(relate),
       (ada)-[:KNOWS]->(grace);
EOF
relate query --database ./team.rl < team.cypher
```

## Read the error

Run the failing command again with `--mode envelope` and print the exit code. In this example, the :term[store]{id=store}'s name is misspelled, `tema.rl`, so a read-only open finds nothing to open:

```bash verify
relate --database ./tema.rl --read-only --mode envelope "MATCH (p:Person) RETURN count(p) AS people"
echo "exit=$?"
```

The path starts with the working directory, shown as `<dir>`. The first line is stderr, the second the :term[error object]{id=error-object} on stdout:

```text
Failed to open Relate: storage error: database not found: <dir>/tema.rl
{"error":{"code":"fatal_error","exit_code":1,"kind":"storage","message":"storage error: database not found: <dir>/tema.rl","retryable":false}}
exit=1
```

The error object's `code` is the class and `exit_code` the exit code, `kind` narrows the class, and `retryable` says whether running the same command again can succeed. `retryable` is `true` for a write-write conflict (exit 5) and for a `--concurrent-logical-workspace-limit` refusal while other statements hold the shared pool (exit 1, kind `resource`; reachable when statements run concurrently, as under `relate serve`). A one-shot CLI run meets only the first. A message's start is enough to find its row: `<name>` marks a part that varies, and `…` marks text left out.

## Collect a report

When a row says to report, or no row fits, these four things let someone else reproduce the problem without your data:

| Part | How to get it |
| --- | --- |
| The relate version | `relate --version`; `relate --version --json` adds the operating system and architecture |
| The store's layout, format, and counts | `relate info --database <path> --json`, which reads metadata only: layout, format, counts, and each index and constraint with its label and property keys, never property values |
| The error object and exit code | The failing command with `--mode envelope`, then `echo "exit=$?"` |
| The statement and the flags | The command line as run, with any `RELATE_` environment variables that were set |

The version check prints two lines:

```bash verify
relate --version
```

```text
Relate v0.16.1
License: Apache 2.0 (binary)
```

## Verify

After the fix, the command that failed exits 0. With the store's name spelled right:

```bash verify
relate --database ./team.rl --read-only --mode envelope "MATCH (p:Person) RETURN count(p) AS people"
echo "exit=$?"
```

```text
{"columnTypes":["INTEGER"],"columns":["people"],"notifications":[],"rows":[{"people":3}],"truncated":false}
exit=0
```

## If it goes wrong

- **The message is in no table.** Search the [errors reference](/docs/reference/errors) for its first words; it lists every error with its cause and remedy.
- **The exit code is 3, 4, or 8.** relate reserves those codes and doesn't produce them. Check which program in the pipeline returned it ([exit codes](/docs/reference/cli/exit-codes-and-errors)).
- **`internal error`.** An engine invariant failed, which is not the statement's fault. [Collect a report](#collect-a-report) with the statement that caused it.
