Getting Started

This tutorial walks you through installing CypherLite and running your first Cypher query. By the end, you will have a working graph database on your machine.

Prerequisites​

You need the Rust toolchain (rustup + cargo) installed on your system.

cargo --version
# cargo 1.x

Install CypherLite​

Clone the repository and build the binary:

git clone https://github.com/neo4j-labs/cypherlite.git
cd cypherlite
cargo build --release

The binary is at target/release/cypherlite. Verify it works:

./target/release/cypherlite -version
# CypherLite v0.6.1

For convenience, the rest of this tutorial assumes the binary is on your PATH or in the current directory as ./cypherlite (e.g. cp target/release/cypherlite .).

Start the interactive shell​

Launch CypherLite with an in-memory database:

./cypherlite

You'll see a short banner and the interactive prompt:

CypherLite 0.6.1. End statements with ;  (.quit to exit)
cypher>

The shell is deliberately minimal: statements submit on a terminating ; (multi-line input shows a ...> continuation prompt) and dot-commands submit on Enter. On a TTY the prompt uses readline-style editing (arrow keys, Home/End) and in-session history (ADR-0073). There is no tab completion or persistent history file. Type .help for the command summary and .quit to exit. Ctrl-C cancels the current buffer; Ctrl-D or .quit leaves the shell.

Run your first query​

Type a simple RETURN statement to verify everything works:

RETURN 'Hello, Graph World!' AS message;

You should see (string values render as quoted Cypher literals):

+-----------------------+
| message               |
+-----------------------+
| "Hello, Graph World!" |
+-----------------------+

Create your first node​

Nodes are the core entities in a graph. Create one with a label and properties:

CREATE (p:Person {name: 'Alice', age: 30});

A mutating statement with no RETURN prints nothing — it commits durably on success (autocommit) and the next prompt appears.

Query it back​

Use MATCH to find nodes:

MATCH (p:Person) RETURN p.name, p.age;
+---------+-------+
| p.name  | p.age |
+---------+-------+
| "Alice" | 30    |
+---------+-------+

Open a database directory​

The product CLI persists to a directory (WAL + a snapshot codec), not a single .db file.

# Default snapshot codec: Parquet shards + manifest.json + wal/
./cypherlite ./mydata

# Readable CypherLite GraphData snapshot (graph.json), same WAL
./cypherlite --snapshot-format json ./mydata-json

Creates, queries, and checkpoints stay on cypherlite::Database. Reopen the same path later without --snapshot-format; the codec is stored in manifest.json. Passing the other format on an existing directory is an error.

Layout:

CodecHow to choose (empty dir only)Store files
parquet (default)omit the flag, or --snapshot-format parquetmanifest.json, nodes/{lo}-{hi}.parquet, relationships/…, wal/
json--snapshot-format json or CYPHERLITE_SNAPSHOT_FORMAT=jsonmanifest.json, graph.json (full rewrite each checkpoint), wal/

To import an old CypherLite JSON .db file:

mkdir -p ./imported
cp old-graph.db ./imported/graph.json
./cypherlite --snapshot-format json ./imported

Python and other language bindings open the same directory layout. Existing single-file GraphStore JSON databases require the explicit import procedure above; bindings do not auto-migrate them. See Storage Engine.

Useful dot-commands​

Type .help at the prompt to see the command summary. The shell implements exactly seven dot-commands — the six kept by the ADR-0058 surface reduction plus the restored .timer; anything else starting with . errors unknown command:

CommandDescription
.helpShow the command summary
.begin / .commit / .rollbackExplicit transactions
.checkpointForce an immediate checkpoint
.timer on|offToggle per-statement wall-clock timing (default off)
.quitExit CypherLite

See the Dot-Commands Reference for details.

Optional: import GraphStore JSON​

Copy a withdrawn GraphStore .db file to graph.json and open with --snapshot-format json (ADR-0052).
