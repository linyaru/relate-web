Every `relate` run ends with an exit code from one closed table, so a script or an agent can branch on the class of failure without parsing a message:

| Code | Class | Meaning |
| --- | --- | --- |
| 0 | `success` | Success, including an empty result |
| 1 | `fatal_error` | A runtime failure: store open or I/O error, capacity limit, execution failure |
| 2 | `usage_error` | An unknown flag, a bad or missing value, an extra positional argument |
| 5 | `conflict` | A write-write conflict, or the store is locked by another opener |
| 6 | `validation_error` | The statement is rejected: syntax, semantic or type error, or a write on a read-only store |
| 7 | `timeout` | A statement ran longer than `--timeout` |

In the JSON output modes, a failed query run also prints an :term[error object]{id=error-object} whose `exit_code` equals the process's. `relate agent-context` prints the same table for the installed version.
