In about ten minutes, we give an agent a memory that outlives its session: one file, `memory.rl`, holding what it learned, where it learned it, and which later fact corrected an earlier one. We write two episodes from the command line and a third over MCP, the way an agent host does, then recall by meaning. The data model comes from [Model agent memory](/docs/guides/agents/model-agent-memory), which explains each label and property; this page builds it and uses it.

## Prerequisites

- `relate` on your `PATH`: `relate --version` prints `Relate v0.1.2` on its first line. The [install page](/docs/get-started/install) takes about two minutes.
- A terminal on macOS or Linux, in an empty directory.

## Create the memory store

A memory attaches to the things it is about. Ours is about the shared example graph, three people and two projects, and every person and project becomes an `Entity` with a lowercase `key`. The schema adds a :term[constraint]{id=constraint} that keeps one node per key, episode and fact, an index on the fact's slot, and a vector index for recall by meaning. Write it all to a script:

```bash verify
cat > memory.cypher <<'EOF'
CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
       (grace:Person {name: 'Grace', role: 'engineer'}),
       (noor:Person {name: 'Noor', role: 'maintainer'}),
       (relate:Project {name: 'relate', language: 'Rust'}),
       (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
       (ada)-[:WORKS_ON {since: 2024}]->(relate),
       (grace)-[:WORKS_ON {since: 2023}]->(relate),
       (grace)-[:WORKS_ON {since: 2022}]->(tck),
       (noor)-[:MAINTAINS]->(relate),
       (ada)-[:KNOWS]->(grace);
MATCH (n) WHERE n:Person OR n:Project SET n:Entity, n.key = toLower(n.name);
CREATE CONSTRAINT entity_key IF NOT EXISTS FOR (e:Entity) REQUIRE e.key IS UNIQUE;
CREATE CONSTRAINT episode_id IF NOT EXISTS FOR (ep:Episode) REQUIRE ep.id IS UNIQUE;
CREATE CONSTRAINT fact_id IF NOT EXISTS FOR (f:Fact) REQUIRE f.id IS UNIQUE;
CREATE INDEX fact_slot IF NOT EXISTS FOR (f:Fact) ON (f.slot);
CREATE VECTOR INDEX fact_embedding IF NOT EXISTS
  FOR (f:Fact) ON (f.embedding) WITH [f.closedAt]
  OPTIONS {indexConfig: {`vector.dimensions`: 4, `vector.similarity_function`: 'cosine'}};
MATCH (e:Entity) RETURN e.key AS key ORDER BY key;
EOF
```

Run it into a new :term[store]{id=store}, `memory.rl`, which relate creates because nothing is there yet:

```bash verify
relate query --database ./memory.rl --mode table < memory.cypher
```

```text
+------------------+
| key              |
+------------------+
| "ada"            |
| "grace"          |
| "noor"           |
| "opencypher-tck" |
| "relate"         |
+------------------+
```

Five entities, each with the key a memory write matches on. The vector index takes 4-dimension vectors so this page's results never change; a real embedding model's vectors have hundreds of dimensions.

## Remember a session from the CLI

An episode is one thing the agent saw: a message, or a tool call and its result. From each one, the agent's model extracts a fact. One statement writes a batch of episodes, each with its fact: the fact comes `FROM` its episode and is `ABOUT` the entities it names. When a new fact answers the same slot as an older current one, the statement closes the older one and links them with `SUPERSEDES`, so nothing is deleted. Save it:

```bash verify
cat > remember.cypher <<'EOF'
UNWIND $episodes AS m
CREATE (ep:Episode {id: m.id, session: m.session, kind: m.kind, at: datetime(m.at), text: m.text})
CREATE (f:Fact {id: m.factId, text: m.fact, slot: m.slot, validFrom: datetime(m.validFrom),
                recordedAt: datetime(m.at), embedding: vector(m.embedding, 4, FLOAT32)})
CREATE (f)-[:FROM]->(ep)
WITH ep, f, m
CALL (ep, f, m) {
  UNWIND m.about AS key
  MATCH (n:Entity {key: key})
  CREATE (ep)-[:MENTIONS]->(n), (f)-[:ABOUT]->(n)
}
CALL (f) {
  MATCH (old:Fact {slot: f.slot}) WHERE old.recordedAt < f.recordedAt AND old.closedAt IS NULL
  SET old.validTo = f.validFrom, old.closedAt = f.recordedAt
  CREATE (f)-[:SUPERSEDES]->(old)
  RETURN count(old) AS replaced
}
RETURN ep.id AS episode, f.text AS fact, replaced;
EOF
```

In session `s1`, the agent hears two messages. This file is what the extraction produced for them, embeddings included:

```bash verify
cat > session1.json <<'EOF'
[
  {"id": "e1", "session": "s1", "kind": "message", "at": "2026-03-02T10:00:00Z",
   "text": "Grace does the release review for relate.", "about": ["grace", "relate"],
   "factId": "f1", "fact": "Grace reviews each relate release.", "slot": "relate/release-reviewer",
   "validFrom": "2026-01-05T00:00:00Z", "embedding": [0.9, 0.1, 0.0, 0.2]},
  {"id": "e2", "session": "s1", "kind": "message", "at": "2026-03-02T10:05:00Z",
   "text": "Noor goes through new relate issues every Monday.", "about": ["noor", "relate"],
   "factId": "f2", "fact": "Noor triages new relate issues on Mondays.", "slot": "relate/triage",
   "validFrom": "2026-02-02T00:00:00Z", "embedding": [0.1, 0.9, 0.2, 0.0]}
]
EOF
```

`--fetch-params episodes=session1.json` reads the file and binds it as `$episodes`. Write the session:

```bash verify
relate query --database ./memory.rl --mode table --fetch-params episodes=session1.json < remember.cypher
```

```text
+---------+----------------------------------------------+----------+
| episode | fact                                         | replaced |
+---------+----------------------------------------------+----------+
| "e1"    | "Grace reviews each relate release."         | 0        |
| "e2"    | "Noor triages new relate issues on Mondays." | 0        |
+---------+----------------------------------------------+----------+
```

Two episodes, two facts, and nothing replaced: the memory had nothing to correct yet.

## Remember a tool call over MCP

An agent host talks to relate over :term[MCP]{id=mcp} (the Model Context Protocol): it starts `relate serve --mcp stdio` and sends JSON-RPC messages, one per line, on its stdin. In session `s2`, a tool call reads the repository's owners file and finds that Ada took over release review on 10 March. These three lines are what a host sends: `initialize`, the `notifications/initialized` notification, then a `write_cypher` call with the same statement and the new episode as its `parameters`:

```bash verify
cat > requests.jsonl <<'EOF'
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"shell","version":"0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"write_cypher","arguments":{"statement":"UNWIND $episodes AS m CREATE (ep:Episode {id: m.id, session: m.session, kind: m.kind, at: datetime(m.at), text: m.text}) CREATE (f:Fact {id: m.factId, text: m.fact, slot: m.slot, validFrom: datetime(m.validFrom), recordedAt: datetime(m.at), embedding: vector(m.embedding, 4, FLOAT32)}) CREATE (f)-[:FROM]->(ep) WITH ep, f, m CALL (ep, f, m) { UNWIND m.about AS key MATCH (n:Entity {key: key}) CREATE (ep)-[:MENTIONS]->(n), (f)-[:ABOUT]->(n) } CALL (f) { MATCH (old:Fact {slot: f.slot}) WHERE old.recordedAt < f.recordedAt AND old.closedAt IS NULL SET old.validTo = f.validFrom, old.closedAt = f.recordedAt CREATE (f)-[:SUPERSEDES]->(old) RETURN count(old) AS replaced } RETURN ep.id AS episode, f.text AS fact, replaced","parameters":{"episodes":[{"id":"e3","session":"s2","kind":"tool_call","at":"2026-03-20T09:00:00Z","text":"read_file CODEOWNERS: release/ @ada","about":["ada","relate"],"factId":"f3","fact":"Ada reviews each relate release.","slot":"relate/release-reviewer","validFrom":"2026-03-10T00:00:00Z","embedding":[0.85,0.15,0.05,0.25]}]}}}}
EOF
```

Now play the host. This server opens the store writable on purpose, because this step writes; a server that only recalls takes `--read-only`, as in [Connect over MCP](/docs/guides/agents/connect-over-mcp). The replies go to `replies.jsonl`, and relate's own status lines to the terminal:

{/* docs-check-ignore trust-read-only */}
```bash verify
relate serve --mcp stdio --database ./memory.rl < requests.jsonl > replies.jsonl
```

```text
serve: MCP (stdio) serving on stdin/stdout (auth: none)
serve: stdin closed, shutting down
```

The server answered each request and stopped when its input ended, as it does when a host closes it. `replies.jsonl` holds two lines, since a notification gets no reply. The first names the server, `relate-mcp` 0.1.2. The second is the write's result as JSON text inside the reply: `write_cypher` returns counters, not rows, so it shows `"nodes_created":2` and `"relationships_created":6`, an empty `rows`, and timings that change on every run. Let's read the store to see what the write did:

```bash verify
relate --database ./memory.rl --read-only --mode table "MATCH (f:Fact)-[:FROM]->(ep:Episode) RETURN ep.id AS episode, ep.kind AS kind, f.text AS fact, f.closedAt IS NULL AS current ORDER BY episode"
```

```text
+---------+-------------+----------------------------------------------+---------+
| episode | kind        | fact                                         | current |
+---------+-------------+----------------------------------------------+---------+
| "e1"    | "message"   | "Grace reviews each relate release."         | false   |
| "e2"    | "message"   | "Noor triages new relate issues on Mondays." | true    |
| "e3"    | "tool_call" | "Ada reviews each relate release."           | true    |
+---------+-------------+----------------------------------------------+---------+
```

Notice that Grace's fact is no longer current, and it is still there. The tool call corrected it, and the memory kept both.

## Recall by meaning

A recall takes the embedding of a question, finds the nearest facts that are still current, and brings back the evidence for each and what it replaced. The cells in this section run in your browser, on an in-memory store with the same engine: the first two hold the same memory as `memory.rl`, written in one batch, and the third is the recall.

```cypher run name=memory
CREATE (ada:Person {name: 'Ada', role: 'engineer'}),
       (grace:Person {name: 'Grace', role: 'engineer'}),
       (noor:Person {name: 'Noor', role: 'maintainer'}),
       (relate:Project {name: 'relate', language: 'Rust'}),
       (tck:Project {name: 'opencypher-tck', language: 'Gherkin'}),
       (ada)-[:WORKS_ON {since: 2024}]->(relate),
       (grace)-[:WORKS_ON {since: 2023}]->(relate),
       (grace)-[:WORKS_ON {since: 2022}]->(tck),
       (noor)-[:MAINTAINS]->(relate),
       (ada)-[:KNOWS]->(grace);
MATCH (n) WHERE n:Person OR n:Project SET n:Entity, n.key = toLower(n.name);
CREATE CONSTRAINT entity_key IF NOT EXISTS FOR (e:Entity) REQUIRE e.key IS UNIQUE;
CREATE CONSTRAINT episode_id IF NOT EXISTS FOR (ep:Episode) REQUIRE ep.id IS UNIQUE;
CREATE CONSTRAINT fact_id IF NOT EXISTS FOR (f:Fact) REQUIRE f.id IS UNIQUE;
CREATE INDEX fact_slot IF NOT EXISTS FOR (f:Fact) ON (f.slot);
CREATE VECTOR INDEX fact_embedding IF NOT EXISTS
  FOR (f:Fact) ON (f.embedding) WITH [f.closedAt]
  OPTIONS {indexConfig: {`vector.dimensions`: 4, `vector.similarity_function`: 'cosine'}};
MATCH (e:Entity) RETURN e.key AS key ORDER BY key
```

```cypher run name=remember params=episodes
CREATE (f:Fact {id: m.factId, text: m.fact, slot: m.slot, validFrom: datetime(m.validFrom),

  SET old.validTo = f.validFrom, old.closedAt = f.recordedAt

  RETURN count(old) AS replaced
}
RETURN ep.id AS episode, f.text AS fact, replaced
```

The question is "Who reviews relate releases?", and this is its embedding:

```json data=question
{"vector": [0.88, 0.12, 0.02, 0.22], "k": 2}
```

```cypher run name=recall params=question
MATCH (f:Fact)
SEARCH f IN (VECTOR INDEX fact_embedding FOR $vector WHERE f.closedAt IS NULL LIMIT $k) SCORE AS score
MATCH (f)-[:FROM]->(ep:Episode)
RETURN f.text AS memory, round(score, 4) AS score, ep.text AS evidence,
       COLLECT { MATCH (f)-[:SUPERSEDES]->(old:Fact) RETURN old.text } AS replaced
ORDER BY score DESC
```

Grace's fact is the nearest by meaning, and it does not come back: the `WHERE` inside the search drops closed facts before the `LIMIT` counts. Ada's fact answers, with the tool call it rests on and the fact it replaced.

## Recall from the terminal

The same recall runs against `memory.rl`. Save it as a script:

```bash verify
cat > recall.cypher <<'EOF'
MATCH (f:Fact)
SEARCH f IN (VECTOR INDEX fact_embedding FOR $vector WHERE f.closedAt IS NULL LIMIT $k) SCORE AS score
MATCH (f)-[:FROM]->(ep:Episode)
RETURN f.text AS memory, round(score, 4) AS score, ep.text AS evidence,
       COLLECT { MATCH (f)-[:SUPERSEDES]->(old:Fact) RETURN old.text } AS replaced
ORDER BY score DESC;
EOF
```

A person reads a table; an agent parses the :term[envelope]{id=envelope}, one JSON object per result, and branches on the :term[exit code]{id=exit-code}. Both open the store `--read-only`, so a recall can never change the memory.

```text
+----------------------------------------------+--------+-----------------------------------------------------+----------------------------------------+

| "Noor triages new relate issues on Mondays." | 0.6178 | "Noor goes through new relate issues every Monday." | []                                     |
```

## What you built

You have a memory in one file, `memory.rl`: entities, three episodes, and three facts, one of which a later tool call corrected without erasing. It took writes from the command line and from an MCP client with the same statement, and it answers a question by meaning with the evidence attached. The agent's next session starts with an empty prompt and remembers all three facts.
