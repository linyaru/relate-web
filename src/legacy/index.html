quickstart

From zero to graph in 30 seconds.

No server to start, no credentials, no config. One binary, one file.

1

Install the agent skill

Teach your AI agents the CLI, the Cypher dialect, vector and spatial queries — one command, every detected agent. ↓

$ relate skill install
$ relate skill install --agent claude-code
2

Pick a database format ↓

No persistence — everything lives in RAM. Fastest option; ideal for tests, demos, and throwaway exploration.

$ relate --database :memory: 'RETURN 1 AS ok'

A durable directory: fsync'd WAL plus Parquet snapshots (default). Open or create — same command. Checkpoint to graph.json instead with --snapshot-format json.

> Create a local graph database in ./mydata and open a shell→ loading skill relate$ relate --database ./mydata

A .rl bundle packs WAL, snapshots, and catalog into one host file — no sidecar files. Great for shipping a database with an app or agent.

> Create a single-file graph database mydata.rl→ loading skill relate$ relate --database ./mydata.rl
3

Create data

One-shot write with typed parameters — or LOAD CSV, pipe a .cypher file, or pull a subgraph from Neo4j/Aura. ↓

> Create Person nodes for Alice (30) and Bob (28)→ loading skill relate$ relate --database ./mydata 'UNWIND $people AS p CREATE (:Person {…})' --param 'people=[…]'
> Mirror the Person nodes from my Aura database into ./mydata→ loading skill relate$ relate pull --from neo4j.env --query 'MATCH (p:Person) RETURN p' --database ./mydata # durable path required
4

Query it

Same binary, same file — Cypher with a pretty table by default, JSON for pipes and agents. ↓

> List everyone in the database, youngest first, as JSON→ loading skill relate$ relate --database ./mydata 'MATCH (p:Person) RETURN p.name, p.age ORDER BY p.age'

Pick a format — memory, directory, or one file 
> Create a durable graph database in ./mydata, then run a count against it→ loading skill relate
# in-memory — nothing written to disk (also `--database :memory:`)
$ relate query

# durable directory — WAL + Parquet snapshots (the default)
$ relate query --database ./mydata

# one host file — WAL, snapshot and catalog packed into a .rl bundle

Create data — Cypher, typed params, CSV 
> Model a movie graph in ./movies: Person and Movie nodes, ACTED_IN relationships, unique Person names — then import extra people from CSV→ loading skill relate
# schema first: constraint + index
$ relate --database ./movies 'CREATE CONSTRAINT person_id FOR (p:Person) REQUIRE p.name IS UNIQUE'

# write Cypher — MERGE keeps it idempotent
$ relate --database ./movies 'MERGE (m:Movie {title: "The Matrix"})
MERGE (p:Person {name: "Keanu"})
CREATE (p)-[:ACTED_IN {role: "Neo"}]->(m)'

# batch-create from a typed parameter (JSON scalars, repeatable)
$ relate --database ./movies 'UNWIND $cast AS c
MATCH (m:Movie {title: c.movie})
MERGE (p:Person {name: c.name})
CREATE (p)-[:ACTED_IN]->(m)' --param 'cast=[{"movie":"The Matrix","name":"Carrie-Anne"}]'

# import a CSV file (local reads need --load-csv-dir; values arrive as strings — coerce them)
$ relate --database ./movies --load-csv-dir . 'LOAD CSV WITH HEADERS FROM "data/people.csv" AS row
CREATE (:Person {name: row.name, age: toInteger(row.age)})'

Created 1 constraint, 1 Movie, 3 Person nodes, 2 ACTED_IN relationships; imported 3 CSV rows.

> Who acted in The Matrix? Return name and role as JSON.→ loading skill relate

$ relate query --database ./movies
cypher> MATCH (p:Person)-[r:ACTED_IN]->(m:Movie) RETURN p.name, r.role;

+--------------+---------+
| p.name       | r.role  |
+--------------+---------+
| "Keanu"      | "Neo"   |
| "Carrie-Anne"| null    |

docker

One image, one command.

A multi-stage FROM scratch image: musl-native Alpine build, a runtime of three static binaries and the CA bundle. 65 MB, non-root, Bolt on 7687, auth on by default.

run
make docker builds it; the run publishes Bolt and seeds data on first boot 
# build the image and run it: Bolt on 7687, data in ./target/docker-data
$ make docker
$ make docker-run

# a one-off container with a preset credential and a seed query
$ docker run -p 7687:7687 -v "$PWD/data:/data" \
    -e RELATE_AUTH=relate/secret \
    -e RELATE_QUERY="UNWIND range(1,100) AS i CREATE (:Person {id: i})" \
    relate-bolt:0.9.2

# auth is on by default: the generated token is in the startup banner
$ docker logs <container> 2>&1 | grep "generated token"
auth: generated token for user relate: 081024fbd538d05dbd177e0bb5e9808b
# persisted next to the database — the same token across restarts

Config resolution, most to least canonical: container args pass straight to the server (--bind, --auth, TLS flags); a mounted /config/seed.json drives seeding (ordered steps: query, load+query, pull+query); env one-liners (RELATE_QUERY, RELATE_LOAD, RELATE_AUTH). INSTANCES=N runs a test fleet — N servers, ports stepping from the base --bind port (-p 7687-7689:7687-7689 publishes the range). Ctrl-C and docker stop work. See the ADR and the README Docker section for the full contract.

extensions

Userland commands, one mount.

A package that walks a source and writes the graph through MCP tool calls — the host owns the store. Any language that speaks JSON-RPC works.

user guide — scaffold, check, install, run

One command scaffolds a complete package; one function says what it does.

# scaffold a package (sh | py | ts | rust) — manifest, MCP client, TODO-marked walk()
$ relate extension init word-count --lang py
# probe the wiring — the handshake, the flag table, the refusal texts — without installing
$ relate extension check ./word-count
# install and run it: flags come from the manifest's own table
$ relate extension install word-count --from ./word-count
$ relate run word-count --name README.md -d ./mydata

Trust tiers — first-party channel, commit-pinned GitHub releases (--github OWNER/REPO@TAG, the pin recorded in a per-user trust store), or a local directory. Nothing is ever fetched implicitly; every unknown name fails closed naming the install path.

fs-to-graph — the directory tree, as a graph

A first-party extension crate speaking the same MCP stdio wire: one (:File {path, name, extension, size_bytes, content?}) per file, (:Folder)-[:CONTAINS]-> the tree, a fulltext index over names and contents, idempotent re-runs on the path key.

$ relate extension install fs-to-graph
installed fs-to-graph 0.13.0 (first-party)
$ relate run fs-to-graph -d ./mydata ./project
fs-to-graph: 312 File, 41 Folder, 353 CONTAINS in 0.8s

# the graph is meant to be searched — the fulltext index is built in
$ relate -d ./mydata "MATCH (f:File) SEARCH f IN (FULLTEXT INDEX file_content FOR 'trust boundary' LIMIT 20) RETURN f.path"
git-to-graph — who wrote what, when, and what changes together

The checkout's history joined onto the same :File.path keys: (:Person {email, name})-[:AUTHORED]->(:Commit {sha, subject, authored_at, files_changed})-[:TOUCHED]->(:File {path}), plus CO_CHANGED pairs per commit — the co-change signal for refactoring candidates.

$ relate extension install git-to-graph
$ relate run git-to-graph -d ./mydata --max-commits 5000
git-to-graph: 5000 Commit, 38 Person, 41200 TOUCHED, 96400 CO_CHANGED in 41s

# files that change together most often — refactor candidates
$ relate -d ./mydata "MATCH (a:File)-[c:CO_CHANGED]->(b:File) WHERE c.count > 20 RETURN a.path, b.path, c.count ORDER BY c.count DESC LIMIT 10"

Worked examples — so-to-graph imports live Stack Exchange questions into the notebook's schema, three times: bash with the inlined wire kit, Python on the official MCP SDK, TypeScript on the TS SDK. The sources are in the repo.

dungeon — the keep, as a graph you walk

A MUD-style game as a first-party extension child: every verb — move, look, take, give, ask — is one Cypher statement against the store the host owns, and the map is an explored window the child renders from the rooms you have entered. The starter quest is a trade with a dragon.

# from a checkout — or any extension package directory
$ relate extension install dungeon --from extensions/relate-dungeon/package
# the play verb prints a self-contained bash runner; process substitution keeps the prompt interactive
$ bash <(relate run dungeon --command play) keep.rl
The road ends at a flight of stone steps. … You have come for the trade.
You — hp 10, xp 0, carrying: nothing
· · · · | · · · ·
· · · - @ - · · ·
[Entrance] A cool draft blows down from the steps above. Torchlight flickers on worn stone.
exits: n, e, w
dungeon> n
dungeon> ask bard hint
Bard: Take the key from the armory west of the hall, then follow the corridors north to the throne room. The cellar lies beyond it.

The whole game is the store — rooms, passages, characters and their chat, items and the locks they open live in your .rl file; the child holds no state, so every turn is one relate run call and any session resumes where it left off.

from other MCP clients — stdio and streamable HTTP

The same tool surface serves plain MCP clients, not just extensions: six tools, one table — get_schema, update_schema, read_cypher, write_cypher, batch_cypher, report_output.

# stdio: register as a command in any MCP host (Claude Code, Claude Desktop, …)
#   command: relate  args: serve --mcp stdio -d ./mydata

# streamable HTTP: one JSON-RPC message per POST, basic auth
$ relate serve --mcp 7800 --auth relate:secret -d ./mydata
$ curl -s relate:secret@127.0.0.1:7800/ -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Gates — read_cypher admits pure reads only; write_cypher/batch_cypher refuse pure reads and cap rows and statements per call; update_schema admits DDL only. Hosts auto-approve the read-only tool; everything else asks.

implementers — the wire under the hood, and publishing

The child is the MCP client; the host is the server. JSON-RPC 2.0 on the pipes: the child writes initialize then tools/call requests on stdout, the host answers on stdin. The store is host property — the child never even sees the database path.

# the wire kit: pure std + serde_json, linkable from any child language
#   relate-wire/src/mcp/{protocol,tools,child}.rs
#   Request/Response records, the one tool table, the child-side client kit

# a child's whole job: handshake, then parameterized calls under the caps
→ {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18",…}}
← {"jsonrpc":"2.0","id":1,"result":{"serverInfo":{…},"capacity":{…},"commitPolicy":"per-batch"}}
→ {"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"write_cypher",
     "arguments":{"statement":"UNWIND $rows AS r CREATE (:Word {text: r.text})","parameters":{"rows":[…]}}}}

Publishing — a package is a directory with a manifest (extension.json), an executable, and its inputs; extension check validates the wiring before any install. First-party packages ship through the signed channel; anyone else ships a GitHub release and users install it commit-pinned. The full contract — manifest schema, caps, commit policies, error classes — is the extension spec; the design record is ADR-0429 through ADR-0447.

reference

The concise reference.

CLI — flags, commands, exit codes

relate [OPTIONS] [--database PATH] [QUERY|-c QUERY] — the store is --database / -d (:memory: by default); the first positional is the statement. relate query [STATEMENT] [--database PATH] is the statement-session verb: with a statement it runs once, without one it reads a stdin script or opens the interactive shell on a terminal. No statement and no query verb opens the interactive shell on a terminal; piped or redirected stdin prints help and exits.

$ relate query                              # in-memory interactive shell
$ relate query --database ./mydata    # durable directory, interactive
$ relate --database ./mydata.rl "RETURN 1"      # single-file bundle, one-shot
$ relate --database :memory: "RETURN 1 + 2 AS sum"  # one-shot, no files
$ relate --load ./mydata.rl "MATCH (n) RETURN count(n)"  # bundle into memory, query it
$ relate query --database ./mydata < setup.cypher  # pipe a script

Flags — single- and double-dash both accepted; -- ends flag parsing:

-h, --help        usage
--version         version
-d, --database PATH   database directory, .rl bundle, or :memory: (default :memory:)
--json / --csv / --markdown / --toon    output format shortcuts
--mode M          table | csv | json | jsonl | envelope | markdown | cypher | toon | speedscope
--format M        alias of --mode (the neo4j-cli spelling)
--pretty          indent JSON even when piped (piped JSON is compact by default)
--noheader        drop column headers
--width N         wrap the table to N display columns (default terminal width, else natural)
--max-rows N     rows printed per statement; 0 unlimited (agent default 100)
--timeout DURATION  cancel a long statement (500ms, 10s, 2m; 0 disables; exit 7)
--param N=V       bind a Cypher parameter (repeatable, JSON scalar)
--fetch-params N=SRC  fetch a URL or read a file, bind its JSON as $N (repeatable)
-c, --command Q   one-shot query
--snapshot-format F           parquet | json | markdown (empty directory only)
--wal-dir DIR               WAL directory (default <DATABASE>/wal)
--checkpoint-interval-secs N  timed checkpoint period, 0 disables
--logical-graph-size-limit SIZE   live graph + index cap (bytes, mb/mib/gb/gib; 0/unset unlimited)
--concurrent-logical-workspace-limit SIZE  shared query workspace pool; a positive value turns admission on
--durability-mode M         WAL durability (full|everysecond|snapshot; default full)
--load-csv-dir PATH         allow local LOAD CSV under this directory (default denied)
--read-only[=FRESH]   open an existing database without writing or checkpointing;
                       FRESH is snapshot (default) or live — tail the WAL (the former --follow)
--load SOURCE       load a store's content from a .rl path, directory, or https URL:
                       into :memory: (turned into the in-memory store, source released)
                       or a new --database path (cloned there)
--namespace NAME            session namespace (neo4j|system|system_ontologies)

$ relate push --to neo4j.env --database ./mydata --dry-run
# push: pull's mirror — scoped subgraph of ./mydata → Neo4j/Aura over the same
# Query API v2 and credentials file; merge keys from the store's key constraints
$ relate extension install fs-to-graph · relate run fs-to-graph ./src --database ./code-graph
# the lab importers are extensions now: install from the signed channel, then `run` drives it;
# fs-to-graph imports a directory tree as (:Folder)-[:CONTAINS]->(:Folder|:File),
# files keep content up to --max-content-bytes (default 65536); MERGEd on path, re-import is a no-op

Run relate <COMMAND> --help for a command's own synopsis and flags (top-level --help stays short; both end with examples — RELATE_HELP_EXAMPLES=0 hides them). --version --json prints one JSON line. An unknown flag close to a real one gets a Did you mean '--read-only'? suggestion before the usage line; a parse error whose first word is a near-miss of a command gains a did you mean "query"? line under the error. Exit codes: 0 success, 2 usage error, 6 rejected statement (syntax, semantic or type error — including a write on a --read-only database), 5 write conflict or store locked by another opener, 7 statement timed out (--timeout), 1 other runtime failure. In json, jsonl and envelope modes a failure also prints {"error":{code,exit_code,kind,message,retryable,…}} on stdout; a failed multi-statement run adds statement N of M failed; … on stderr. A batch write that applies no change prints note: write statement changed nothing; the graph is unchanged on stderr (a .commit whose transaction changed nothing prints its own note); stdout and exit codes are unchanged. A path that collides with a command word stays reachable via ./ or after --.

Environment variables — each mirrors a flag:

RELATE_SNAPSHOT_FORMAT=json        # snapshot codec for an empty directory
RELATE_CHECKPOINT_INTERVAL_SECS=300 # timed checkpoint period, 0 disables
RELATE_LOGICAL_GRAPH_SIZE_LIMIT=4gb # live graph + index cap
RELATE_TELEMETRY=0 · DO_NOT_TRACK=1   # opt out of CLI metrics
RELATE_MAX_ROWS=0 · RELATE_HELP_EXAMPLES=0  # lift the agent row cap / hide help examples
NEO4J_URI=… NEO4J_USERNAME=… NEO4J_PASSWORD=…  # pull source when --from is omitted
RELATE_LOAD_CSV_DIR=…             # allowed LOAD CSV directory

Telemetry is anonymous — command shapes, feature flags, an anonymous install id, a coarse environment tag. It never sends query text, file paths, or data, defaults to on, and only the standalone CLI collects it (not the embedded Rust, Python, or WASM APIs).

Shell dot-commands

Inside the interactive shell, dot-commands submit on Enter (Cypher statements end with ;):

cypher> .help          # command summary
cypher> .quit          # exit (alias: .exit; Ctrl-D works too)
cypher> .begin         # explicit transaction
cypher> .commit        # append combined redo once
cypher> .rollback      # discard the transaction
cypher> .checkpoint    # pin LSN, dump snapshot, recycle WAL
cypher> .info          # store metadata + live counts + catalog
cypher> .timer on      # per-statement timing

Default is auto-commit: one statement, one durable WAL commit. Explicit transactions share one snapshot; a dropped connection rolls back. Exiting with an open transaction rolls it back with a warning (batch modes exit 1). Ctrl-C cancels the current buffer.

Output formats

Eight formats, selected by flags — no in-session .mode command:

$ relate --database ./mydata "MATCH (p:Person) RETURN p.name, p.age"      # table (default)
$ relate -csv --noheader --database ./mydata "…" > people.csv
$ relate -json --database ./mydata "…" > people.json   # compact when piped; --pretty forces indent
$ relate --mode jsonl --database ./mydata "…" | jq .          # one object per line
$ relate --toon --database ./mydata "…"                 # rows[N]{col,…}: header, one line per row
$ relate --mode envelope --database ./mydata "…"            # {columns, rows, truncated, notifications} per result set
$ relate --mode markdown --database ./mydata "…"              # for docs & agents
$ relate --mode cypher --database ./mydata "…"                 # Cypher literals

EXPLAIN and PROFILE render the query's plan tree — operators with row estimates; PROFILE adds measured rows, time, db hits (broken into hops / neighbor walks / node reads), and memory per operator, marks an operator that never ran, and flags typed warnings (cartesian product, label-less scan while a label index exists, a 10× estimate overshoot). A scan-shaped MATCH executed as batch operators shows a [batched] suffix in Details, plus [zone-skips N] when per-column zone maps skipped a conjunct. One more mode exports that tree:

$ relate --mode speedscope --database ./mydata "PROFILE …" > plan.json   # load at speedscope.app

EXPLAIN and PROFILE also derive Neo4j-style query notifications — twelve kinds (unknown label / relationship type / property key, deprecated function or procedure, cartesian product, unbounded variable-length pattern, …), each with a code, GQLSTATUS, severity, and remedy. Table mode prints a Notifications: block on stderr, markdown appends it, toon prints a notifications: section, and envelope always carries the complete list under notifications (an empty array on a plain run).

Flags work in one-shot mode, pipe mode, and the interactive shell. Under a detected agent harness a statement prints at most 100 rows (warns on stderr, exits 0; --max-rows 0 lifts it), envelope reports "truncated": true, and a piped run's default format is toon instead of jsonl (an explicit --mode/shortcut always wins).

100% openCypher TCK 2024.3 — 3,892 / 3,892 scenarios pass, strict run (error class, error phase, side effects) enforced in CI. See the compliance report. On top of that, Relate ships full GQL alignment and the Cypher 25 feature set.

Storage — WAL + one snapshot codec

The matcher runs on an in-memory graph; disk is for crash recovery. One write path: append redo to the fsync'd WAL, then apply. Snapshots capture already-committed state.

Shapes:

relate --database :memory:              # RAM only, nothing written
relate --database ./mydata              # dir: WAL + Parquet shards (default)
relate --snapshot-format json --database ./d  # dir: WAL + graph.json (empty dir only)
relate --snapshot-format markdown --database ./vault  # markdown vault: one Label/name.md per node — frontmatter
                       # properties, body text, [[wikilinks]]; .relate/ sidecar holds WAL + manifest;
                       # hand edits while closed are picked up at the next open
relate --database ./mydata.rl             # one host file: WAL + snapshot + catalog
relate --read-only --database ./mydata    # open existing store, no writes or checkpoints
relate --read-only=live --database ./mydata # tail the WAL live (the former --follow)
relate --load ./mydata.rl                 # turn the bundle into the in-memory store — source released
relate --load https://…/graph.rl          # remote .rl fetched to memory (blob links rewritten to raw)
relate clone ./mydata ./backup.rl      # dir → .rl file (reverse: clone ./backup.rl ./d); never writes source

Layout (directory codec):

<dir>/manifest.json
<dir>/nodes/{lo}-{hi}.parquet        # or graph.json for the json codec
<dir>/relationships/{lo}-{hi}.parquet
<dir>/wal/NNNNNNNN.log

One codec per directory — mixing Parquet shards and graph.json is an error. Checkpoints rotate at 64 MiB WAL, 10 000 commits, or a timer (default 300 s, --checkpoint-interval-secs). Crash recovery = load snapshot, replay WAL. --logical-graph-size-limit caps the live graph (logical, not RSS) — the working set must fit in RAM. Optional CDC slots hold WAL recycle until acked. Stores carry a format version — opening an older store migrates it in place, hands-off.

Embedding & remote access

All language clients wrap the same C ABI (relate-ffi) — no parallel protocols. Query results carry the same metadata everywhere: the resolved namespace, the query type (r/w/rw/s), and the statement's structured plan (relate.plan/v1 — operator tree with estimates, PROFILE metrics, and per-operator remedy-bearing warnings; absent on a plain run), from the Rust API through the C ABI to every client. Read-only open is available on every surface — Rust, Bolt, Python, C, JavaScript, Java, Go, and WASM — alongside the CLI's --read-only.

Rust — the public crate:

use relate::Database;
let db = Database::open("./graph.rl")?;
let stats = db.execute("MATCH (n:Person) RETURN n.name")?;

Python — pip install relate-db, then import relate (PyO3, in-process, plus Arrow IPC via execute_arrow). Cursor rows are Records (dicts with attribute access) and cursors carry driver-style conveniences — single(), peek(), graph(), to_df(), to_arrow().

JavaScript — Node: npm install @relate/relate (koffi over the C ABI; the platform package is an auto-selected optional dependency; TypeScript types included). conn.query doubles as a tagged template — interpolated values become auto-named parameters — and returns a Result with object rows, stats, single(), consume(), and graph(). Browser: npm install @relate/relate-wasm — in-memory, or durable OPFS via await RelateDb.open("opfs://name") in a dedicated worker.

Java — com.relate:relate on Maven Central: the plain jar bundles the relate-ffi native for all five platforms (macOS and Linux on arm64/x64, Windows x64) and loads the running platform's copy with no RELATE_LIB or library path; per-platform classifier jars (osx-aarch_64, linux-x86_64, …) carry one platform each. Go — FFI bindings over the same C ABI; prebuilt relate-ffi tarballs ship on the releases page.

Bolt — remote transport for the same engine: point any Bolt client at the relate-bolt server. Basic auth is on by default — a token is generated at startup, printed in the banner, and persisted next to a persistent database (.auth-token); --auth user:password sets your own, --auth none disables. Bolt-over-WebSocket shares the same --bind (on by default, --no-websocket opts out, --ws-allow-origin widens the Origin policy), so neo4j-browser and the browser build of the official JavaScript driver connect out of the box.

$ relate-bolt --help    # serve the database over Bolt
Serve — HTTP Query API, MCP, Bolt on one store

relate serve hosts the network surfaces on one open database until SIGINT/SIGTERM. Each surface gets its own flag and port (loopback only, no defaults; a taken port is a startup error): --http PORT serves the HTTP Query API v2 (POST /db/<name>/query/v2 plus a public GET / discovery document), --mcp PORT the MCP server on its streamable-HTTP transport, and --bolt PORT the Bolt server (Bolt + Bolt-over-WebSocket).

$ relate serve --database ./mydata --http 7474 --mcp 8000 --bolt 7687
$ curl -s -X POST http://127.0.0.1:7474/db/neo4j/query/v2 \
    -u relate:<token> -H 'Content-Type: application/json' \
    -d '{"statement": "MATCH (n) RETURN count(n)"}'

Basic auth is shared by every served surface: by default a token is generated at startup, printed in the banner, and persisted next to a persistent database (.auth-token, mode 0600); --auth user:password (or RELATE_AUTH) presets a credential, --auth none disables. --origin ORIGIN widens the browser Origin policy on the HTTP surface (repeatable; default loopback origins plus https://browser.neo4j.io and https://console.neo4j.io). --read-only serves an existing store without the writer lease, so another process can keep writing it; --read-only=live (native directories only) tails the WAL and keeps showing the writer's commits. --load SOURCE takes the same sources as the CLI — a :memory: target serves the loaded store ephemeral (source released, writes refuse), a -d PATH target creates the store there before serving.

--host HOST overrides the loopback bind (any other host prints a loud warning — serve has no TLS); --mcp stdio serves the MCP stdio transport in the foreground for MCP hosts; --bolt-identity STRING sets the Bolt HELLO server agent. --max-connections N caps process-wide sessions shared by every surface (over cap is accept-then-close; 0 or omit is unlimited; RELATE_MAX_CONNECTIONS), and --max-active-queries N caps concurrent queries (RELATE_MAX_ACTIVE_QUERIES).
